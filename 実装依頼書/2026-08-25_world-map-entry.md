## 1. 目的

キャラ選択(`title.html`)を終えると、いま**いきなり港町フラン `town.html`**(`?town=0` なら酒場)に立つ。
世界のどこに居るのかが一度も提示されないまま、街 → 酒場 → ダンジョンと閉じた画面が続く。
ダンジョンから戻るときも同じで、`index.html` から直接 `town.html` へワープする。

ここへ **1 枚絵のワールドマップを挟み、主人公の駒を街道の上で歩かせて**から街に入る。

**ユーザー決定(2026-08-25)**:

- **操作方式 = 主人公駒を歩かせる**。⭐ 不採用: 「拠点をタップして選ぶだけ」(実装は軽いが世界を移動している感が出ない) /
  「絵を見せるだけの幕」(拠点が増えたとき作り直しになる)
- **歩ける導線はルート(線)で分かるようにする** ← 追加指示。これが §2-4 の設計方針そのものを決めた
- **スコープ = ダンジョン帰還も挟む**。⭐ 不採用: 「キャラ選択の後だけ」(`index.html` を触らずに済むが、
  帰りだけワープするので世界の一貫性が壊れる)
- **素材はこの sample 画像のまま使い、拠点はコードで重ねる**。⭐ 不採用: 「codex1 に地名入りの本番版を描き直させる」
  (絵の完成度は上がるが着手が納品待ちになる)
- **BGM = `fierd.mp3`(出所 = 魔王魂)**。⭐ 不採用: 「v1 は無音」/「既存の合成 `TRACKS`」
- **ルート線 = 点線**。⭐ 不採用: 羊皮紙風の破線 / 足跡
- **6 シナリオの地にも札を置く**(計 7 枚)。⭐ 不採用: 「v1 は港町フランへの導線だけ」
  ⛔ ただし**入れるのは港町フランだけ**。他の 6 枚は地名を見せて歩いて行けるだけ

### 2-2. ⚠⚠⚠ 罠 A — 間に 1 ページ挟むと「一回性のキー」が壊れる

現在、ダンジョン → 街 → 酒場 の間を **3 つの一回性キー**が流れている。

| キー | 書く | 読んで **消す** |
|---|---|---|
| `dragonfighters.exitVia` | `index.html:3085` (`"dungeon"`) / `tavern.html:6771` (`"tavern"`) | `town.html:411` `removeItem` |
| `dragonfighters.enterVia` | `town.html`(看板クリック時) | `tavern.html:1867` `removeItem` |

⛔ **`world.html` はこの 3 つを 1 つも消してはいけない。**

- `exitVia` を消すと → `town.html` が入口を見失い `spawnFor(null)` の fail-safe で
  **必ず酒場前 (10,3)** に立つ。「ダンジョンから帰ったら酒場前」は**一見正しく見えるので黙って壊れる**。
- `lastResult` を消すと → **酒場のリザルト画面が出なくなる**。今日 `town.html` はこのキーに一切触っていない
  (`grep -n lastResult town.html` → 0 件)。`world.html` も同じでなければならない。

⭐ この罠は §8 の負のコントロール `eatvia` / `eatresult` として装置に内蔵させること。

### 2-3. ⚠⚠ 罠 B — 帰還に world を挟むと `?town=0` の撤退路が死ぬ

`dfReturnPage()` は `off`(= `?town=0`)なら `tavern.html` へ直行する。
`off` 判定**より前**に `world.html` へ飛ばす実装にすると、街を丸ごと素通りする撤退スイッチが機能しなくなる。

⛔ 判定の順序は **`?town=0`(街ごと素通り) → `?world=0`(ワールドマップだけ素通り) → `world.html`** の 3 段。
⭐ `?world=0` は `?town=0` とは **独立**にする(相乗りさせると赤が出たときどちらの撤退か切り分けられない。
`?heromark=0` が `?town=0` から独立している前例と同じ)。

### 2-4. ⚠⚠⚠ 罠 C — 「絵の道」と「歩けるデータ」を別々に持つと必ずズレる → **タイルマスクを作らない**

`town.html` は 23x15 の**通行マスク**(`js/town-map.js` の `MASK`)で歩ける場所を決めている。
これをそのまま写すと本チケットでは壊れる。実測:

- 素材は 1536x1024 = **24x16 マス / 1 マス 64px にちょうど乗る**(`1536/64 = 24.0` / `1024/64 = 16.0`)。
  ⭐ `town_phlan.jpg` (1472x960) と違って端を 1px も捨てずに済む。ただし**今回はこの格子を使わない**
  (将来タイル化したくなったときに焼き直しが要らない、という意味だけ)。
- **街道の描き幅は 1 マス 64px に対して実測 ~10px しかない。** 64px マスへ量子化すると
  「絵では道なのにマスが塞ぐ / 絵では原野なのにマスが通す」が大量に出る。
- ユーザーの追加指示「**歩ける導線はルート(線)で分かるように**」は、この問題の答えそのもの。

⛔ **したがって本チケットは通行マスクを作らない。ノードとエッジの「ルートグラフ」を持ち、
そのエッジを画面に線として描く。描く線と歩けるデータは同一の配列から生成する**
(2 つ持つと必ずズレる)。⭐ この罠は §8 の負のコントロール `maskdrift` で押さえる。
