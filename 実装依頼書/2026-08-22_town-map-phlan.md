### §3 ⭐⭐⭐ 「第2の入口」問題の解き方 — クエリを足さず sessionStorage で渡す

依頼書 #6 `title-screen` が名指しで禁じた事項がある(`title.html:515` のコメント):

> ⚠ **遷移先にクエリを足さないこと。** 足すと「ダンジョンから戻る」導線と形が変わり、
> 酒場の入口が 2 種類になる。

案B では 🛡️ と 🌑 の中身が `tavern.html` の中にあるため、素直に作ると
`tavern.html?shop=1` になり、**この禁止事項をそのまま踏む**。

**解: URL は常に素の `tavern.html`。どの扉から入ったかは `sessionStorage` の 1 キーで渡す。**

```js
// ── town.html 側 ──
sessionStorage.setItem("dragonfighters.enterVia", "shop");   // "tavern" | "shop" | "plaza"
location.href = "tavern.html";                                // ★クエリを足さない

// ── tavern.html 側 (初期化の *描画より前*) ──
const via = sessionStorage.getItem("dragonfighters.enterVia");
sessionStorage.removeItem("dragonfighters.enterVia");         // ★一回性。再読込で再発火させない
if (via === "shop")  { /* #tavern を隠したまま */ openShop(); }
if (via === "plaza") { /* 同上 */ enterPlaza(); }
```

なぜこれが正しいか:

- **URL が 1 種類のまま**なので、#6 の禁止事項に触れない
- **キーが無ければ今日とまったく同じ挙動**(= 天然の撤退経路。silent fail-open ではなく
  「素の酒場」という正しい既定へ落ちる)
- `dragonfighters.*` の sessionStorage ハンドオフは、`tavern.html:5212-5236` が
  出発時に既に使っている**この codebase の作法そのもの**
- ⚠ **必ず描画より前に読む**。あとから `openShop()` を呼ぶと酒場の内装が一瞬見えてから
  店が被さる。`title.html:315` が `?title=0` を IIFE の**先頭**で判定したのと同じ理由

## 撤退スイッチ `?town=0` (§11)

// 各ページの初期化の *先頭*

### ⭐ 南橋 (row 9 か row 10 か) の決着 — 面積比では決まらなかった

画素で実測すると **row 9 = 水 27.0% / row 10 = 28.3%** でほぼ互角(橋板は row 9.5〜10.5 に乗る)。
面積だけで選ぶと row 9 になるが、**足元をタイル中心に置く**規則(`town.html` の `FOOT = 0.93`)を

### ⚠ 本文からの意図的な逸脱 (3 件)

1. **マスクの記号を `.` / `#` の 2 種類にしなかった**(§6 からの逸脱)
   §6 は「`ROOM_PAINTINGS_DEF` と同じ記号」と書いているが、同じ本文の STEP2-4 が
   「**歩けない理由を 1 語でまとめない**。水 / 建物 / 露店 / 瓦礫 / 岩を色分けして出す」と要求している。
   両立させるため **塞ぐ側だけを理由ごとの文字**(`~` 水 / `B` 建物 / `s` 露店 / `r` 瓦礫 / `^` 岩)に割った。
   `.` = 歩けるはそのままで、**`.` 以外はすべて塞ぐ**ので `#` 作法の上位互換。
   ⭐ 理由を別ファイルに持つと 2 つのデータが必ずズレる。1 枚のマスクに畳むのが正しいと判断した。

2. **受入条件 8 を「行き先 1 点」ではなく §11 の 2x2 表で測る**
   `?title=0` の行き先だけを `town.html` へ書き換えると、検出器をまた「手段」に縛り直すだけになる。
   `?title=0` 単独 → 街 / `?title=0&town=0` → 酒場 の **2 行を実測**して、
   「2 つの機能が 1 つのスイッチに相乗りしていない」ことを機械的に守る形にした ((8t))。

3. **更新情報は 2 コミット目で件数を増やさず 1 行目を書き直した**
   `227785b` は `3cc3eaf` と同じ機能の修正なので、新項目にすると同じ話が 2 行並ぶ。
   changelog フックは「`changelogList` が HEAD と違うこと」を見るので、書き直しで正しく通る。
