# 1 枚絵の障害物マスクが、絵の岩と半マスずれている箇所を詰める

- **ステータス**: **見送り (2026-08-22)** — STEP1(道具・実測・目視)まで完了。**STEP2 のマスク編集は行わない**とユーザーが決定。末尾の「実装結果」節が唯一の正。
- **起草日**: 2026-08-20
- **対象**: `index.html` の `ROOM_PAINTINGS_DEF` の `blocked`(データのみ)/ 新規 `tools/probe_paint_overlay.js`
- **出自**: 廃坑の壁抜け調査(`2026-08-20_mine-wall-clipping.md`)の残り。あちらは**外周 1 タイルだけ**を直すので、内側のズレは手つかずで残る。

---

## ⚠ このチケットは「実装せよ」ではない

**直すべきタイルの一覧がまだ無い**。先に作るのは一覧ではなく **一覧を作る道具**で、
その出力をユーザーが見て「ここを直す」と決めてから、はじめてマスクを編集する。

**いきなりマスクを書き換えないこと。** 通行不能を増やすのは到達不能バグの新しい入口で、
しかも原因が絵の側にあるので追いにくい(`applyPaintingBlocking` の注記が同じ警告をしている)。

---

## 目的

キャラクターが、絵に岩が描かれている場所の上に立っている / その上を歩いている状態を減らす。

---

## 事実

### S1 配管は正しい。マスクに書いた岩は 100% 通行不能になっている

`__paintBlockProbe()` と `blocked` の `#` を `isTileWall` に突き合わせた結果、n0(321 マス)/ n1(409 マス)ともに **判定漏れ 0**。
→ **直す先はコードではなくデータ**(`blocked` の行文字列)。

### S2 ズレの正体は「タイル単位のマスク」対「サブタイルの絵」

`blocked` は 1 マス = 1 文字。絵の岩はタイル境界に合わせて描かれていないので、

- 岩が 6 割かかっているのに `.` のマス → **キャラが岩の上に立つ**
- 床が 6 割空いているのに `#` のマス → **通れそうな所が通れない**

の 2 方向にズレる。**原理的にゼロにはできない**ので、「目立つ所だけ潰す」が目標。

### S3 対象は goblin-mine の n0 / n1 の 2 枚だけ

`node: true` の 1 枚絵は 14 枚あるが、`blocked` マスクを持つのは **goblin-mine の n0(33x22)と n1(39x23)だけ**。
他 12 枚(他 5 シナリオの n4 / n7、および goblin-mine の n4 / n7)は**マスクを一切持たない = 部屋全体が床**。

- ⚠ ただし n4 / n7 は 7x6 / 9x6 の小部屋で、絵は「床だけ」を描く作法で作られている(P7 の注記)。
  **岩を描いていないのでズレようがない**。だからこのチケットは n0 / n1 に閉じる。

## STEP1 — 一覧を作る道具(まずこれだけ)

`tools/probe_paint_overlay.js` を作る。**assert を持たない目視補助**で、非退行ドライバとは別扱い。

やること:

1. 内蔵サーバ + puppeteer-core で `?diag=1` のページを開き、`startGame()` を通す。
2. `roomPaintings` から絵を取り、1 タイル = 32px の全景キャンバスへ描く。
3. `isTileWall(gx, gy)` が真のマスを **赤 42% で塗る**。タイル境界に薄い白線を引く。
4. 敵の中心タイルに青い印を置く。
5. PNG として書き出す。`--node n0` / `--node n1` で切り替え。

⚠⚠ **判定の出所は必ず `isTileWall`**。`blocked` の行文字列を自分で解釈し直さないこと。
実装とドライバが同じ規則を二度書くと、**両方同じ誤りのとき永久に緑**になる。

⚠ ノードを渡り歩くには `window.__graphRun.enter('n1', 'right')` を使う。**dev ゲート(`?diag=1`)が要る**
(素の配布物では `__graphRun` は生えない)。到着待ちの間、`#choiceDialog` と `#skillCheckOverlay` を
閉じ続けないと `dialogPaused` で止まったままになる。

**この STEP の完了 = 画像 2 枚をユーザーに見せて、直す箇所の指示をもらうところまで。**

## STEP2 — 指示された箇所だけマスクを直す(承認後)

1. `ROOM_PAINTINGS_DEF["goblin-mine"].n0 / .n1` の `blocked` 行文字列を編集する。
2. ⚠ **行数と桁数を `tileBounds` と一致させたまま**にすること。ずれると
   `DFMapDef.paintingBlockedRows` が丸ごと捨て、`console.warn` 1 行だけ残して**障害物が全部消える**。
3. ⚠⚠ 塞ぐ前に、その 1 マスが下のどれでもないことを確認する(`applyPaintingBlocking` の門番が
   数えてくれるが、**数えられた時点で絵かマスクが間違っている**という設計):
   - プレイヤー起点 / 扉のマス / 敵スポーン / 廊下 / ゲートタイル
4. ⚠⚠ **1 マス塞ぐたびに到達性を測り直す**。測り方は mine-wall-clipping の受入条件 §1b と同じで、
   **本番の `aStar` をそのまま呼ぶ**(自前 BFS を書くと 8 方向で繋いでしまい、実際には歩けない道を
   「繋がっている」と報告する)。外周は封じた状態で測ること。

## 受入条件(STEP2 に進んだ場合)

- (a) n1 の 8 区間(入場 → 玉座 / 入場 → s1 / s1 → s2 / s2 → s3 / s3 → s4 / s4 → 奥へ進む /
      引き返し口 / 上の梯子)が **全部到達可能**(本番 `aStar`・外周封鎖済みの状態で)
- (b) n0 の 起点 → 見張り 2 体 が到達可能
- (c) 敵スロット 12 箇所(n0 の 2 + n1 の 10)が **1 つも塞がれていない**
  ⚠ 敵スポーンの救済は**構造壁しか見ない**ので、`obstacleTileMask` に積んでも救われない。
  塞ぐと「樽に埋まった敵が alive で残り、ボスを倒してもクエストがクリアしない」になる。
- (d) `__paintBlockProbe()` の `skipStart` / `skipDoor` / `skipSpawn` / `skipCorridor` が **全部 0**
  (1 以上 = 絵かマスクが間違っている、という設計になっている)
- (e) 廃坑を `?autoplay` で 1 周して `dungeonCleared` に到達する

## 実装結果 (2026-08-22)

**結論: STEP1 まで実施し、STEP2(マスク編集)は見送り。** ズレは S2 のとおり原理的にゼロにできず、
実測すると「絵の上に立つ」も「敵スロットが塞がる」も現時点では実害が出ていなかったため、
ユーザーの判断で閉じた。道具と実測値は残したので、実機で気になる箇所が出たら再開できる。

### 逸脱① STEP1 の道具は **既に存在していた**

`tools/probe_paint_overlay.js` は **#1 (`7c59c44`) のときに作られていた**。
この依頼書の「これから作る」は起草時点(2026-08-20 22:20)の情報で、#1 の実装中に先取りされていた。
⭐ **依頼書が「新規に作る」と書いていても、着手前に実ファイルの有無を見ること。**

### 逸脱② 依頼書の STEP1 仕様に対して、道具に 2 つ欠けがあった → 埋めた

| STEP1 の項目 | 実物 (改良前) | 対応 |
|---|---|---|
| 3. `isTileWall` を赤 42% で塗る | ✅ ただし**赤 1 色**なので、直せるマスと直せないマスが見分けられない | **理由別に塗り分け**へ (赤=マスク / 橙=外周封鎖 / 青紫=岩盤 / 黄=閉じた扉) |
| 4. **敵の中心タイルに青い印** | ❌ 無い(戦車の乱入位置だけだった) | 敵スロットに丸を追加。**塞がっていると縁が赤くなる**(受入条件 (c) を目で見るため) |
| 2. 1 タイル = 32px | ❌ 24px | 32px へ。あわせて**グローバルなタイル座標の目盛り**を追加(「(43,9) を空けて」と指せるように) |

⚠ 判定の出所は改良後も `isTileWall` と同じ 3 つの述語そのもの(`mapData===2` → `isDoorBlocking` →
`obstacleTileMask`)を順に見るだけで、`blocked` の行文字列は一度も解釈していない。

### 実測 — 依頼書の主張の検算

| 主張 | 実測 | 判定 |
|---|---|---|
| S1 マスクの `#` は 100% 通行不能 (n0 321 / n1 409) | `tally.mask` = **321 / 409** | ✅ 一致 |
| S3 `blocked` を持つ `node:true` の絵は n0 / n1 の 2 枚だけ | `node: true` 14 枚中この 2 枚のみ。`tileBounds` も **[3,20,24,52] = 33x22** / **[2,17,24,55] = 39x23** | ✅ 一致 |
| 受入条件 (c) 敵スロットが 1 つも塞がれていない | n0 2 + n1 10 = **12 箇所すべて塞がっていない** | ✅ |

⭐ **新事実: ノード部屋の内側に岩盤 (`mapData===2`) は 0 マス**。
→ 赤で見えるものは**全部このチケットで直せるマスク**で、直せないのは橙の外周 (n0 103 / n1 118 =
`sealRing`・#1 の担当) と黄の扉だけ、という分担が画像で確定した。

⭐⭐ **訂正: 改良前の道具が出していた `n0 right(45,7) ⛔壁` は欠陥ではない。**
`isTileWall` は `isDoorBlocking` も真にするので、**出口タイルに立っている閉じた扉**がそう見えていた。
出口の扉はノードを片付けるまで閉じているのが正常。⚠ **「壁」と一語でまとめる測定器は、
歩けない理由が複数あるとき必ず誤読を生む**(理由別に塗り分けて初めて分かった)。
