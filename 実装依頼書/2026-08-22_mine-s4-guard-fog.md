# 廃坑 s4「南の操車場」へ実質たどり着けない(護衛が霧半径ちょうどで暴かれる)

- **ステータス**: **承認済(着手可)** — 採用は **案 1 修正版 = 護衛を (51,20)/(51,22) へ**(2026-08-22 ユーザー再承認)。⚠ 本文の案 1 の座標 (48,\*) と案 2 は**不採用**。末尾の「決定」節が唯一の正。
- **発見**: 2026-08-22(`tools/probe_p9_tour.js` の周回実測)

## 目的

寄り道 4 か所のうち **s4 だけが実質 4/5 の確率で回れない**状態を、
「行くかどうかをプレイヤーが選べる」という P9 の企画どおりに戻す。

## 背景・現状(実測)

- 玉座 = `(49,21)`、護衛ホブゴブリン 2 体 = `(46,20)` / `(46,22)`
  (`index.html:33875` `N1_GUARD_SLOTS` / `:33876` `N1_BOSS_SLOT`)。
- s4 = `(24,23)`(`index.html` の `detourTable()`)。s3 `(43,7)` → s4 の本番 aStar は
  **41 歩・帯 (玉座から 8 マス) を 0 マス**しか通らない = `driver_grid_p9` の (1e) は緑。
- **にもかかわらず s4 へ着かない。** 原因は帯ではなく **2 つの視界**:

| 何 | 距離 | 出典 |
|---|---|---|
| パーティの霧 `markVisitedAround(pTX,pTY,6)` | 半径 **6**(ユークリッド、`r²=37`) | `index.html:17316` 付近 |
| 敵の索敵 `DETECTION_RANGE` | **1200px = 12.5 タイル** | `index.html:16013` |

1. **(B) 自分の霧で暴く**: 経路上の `(40,22)` から護衛 `(46,22)` は dx=6 → `36 ≤ 37` =
   **ちょうど霧に入る**。`findNearestAliveEnemy()` は「探索済みタイルに居る敵」を返すので、
   暴いた瞬間に護衛が標的になる。
2. **(A) 向こうが先に気づく**: 索敵 12.5 タイルは霧 6 の **2 倍遠い**ので、護衛のほうが
   先に `chase` へ入って迎撃に出てくることもある。

どちらの場合も heroAI の優先順が
**①見えている敵 > ②落し物 > ③`heroForcedGoal`**(`index.html:17318` 以降)なので、
**s4 へ歩いている最中でも引き返して玉座の間の戦いへ入り、そのまま決着する。**

実測: **5 周中 4 周で s4 が未訪問**(2026-08-21 の 3 周 + 2026-08-22 の 2 周)。
⚠ `heroForcedGoal` は決着の瞬間まで `24,23` を指したまま = 「行くのをやめた」のではなく
「**行く途中で終わった**」。

## 実装の方針(案。どれを採るかは承認時に決める)

  `(40,22)` から dx=8 → `64 > 37` で霧に入らない。

  ⚠ ただし索敵 12.5 タイルは依然届くので、(A) の経路は残る = **完全には消えない**。
- **案 2: s4 を西寄りへ動かす**。経路が `(40,22)` を通らなくなる位置へ。
  ⚠ `driver_grid_p9` の §1b/§1c/§1e/§5a を全部回し直すこと。
- **案 3: 何もしない(創発として受け入れる)**。s4 の羊皮紙には既に

## 2026-08-22 追試(計画窓)— **上の「真因」は 2 か所とも実測と食い違う**

道具: `tools/probe_s4_relocate.js`(本番の `aStar` / `isTileWall` / `hasLineOfSight` を
そのまま呼ぶ。外周 1 タイルは禁止して測っている)。

### ① 「経路上の (40,22)」は **s3→s4 の経路上に無い**

本番の aStar が返す s3 (43,7) → s4 (24,23) の 41 歩は:

```
42,7 41,7 41,8 40,8 39,8 38,8 37,8 37,9 37,10 37,11 37,12 36,12 35,12 35,13 35,14
35,15 35,16 36,16 36,17 37,17 37,18 38,18 38,19 38,20 37,20 36,20 35,20 34,20 33,20
32,20 31,20 30,20 29,20 28,20 27,20 26,20 25,20 24,20 24,21 24,22 24,23
```

最南東端は **(38,20)**。護衛 (46,20) までの距離は **8 タイル ちょうど**(dx=8)。
`(40,22)` は 1 マスも踏まない。**入場→s4 の 45 歩も同じ**(最接近 8)。

→ ⚠ `(40,22)` は **#9(ボスラッチ)のログから来た座標**だった。あちらは
  「玉座へ向かう最終行程」の実座標で、s4 への行程ではない。**2 枚のログを混ぜていた。**

### ② 「霧 (半径 6) で暴かれる」は **成立しない**

`markVisitedAround(…, 6)` の判定は `dx²+dy² <= 37`。経路の最接近は 8 タイル = **64 > 37**。
s3→s4・入場→s4 の**両方で霧に入るタイルは 0 マス**(実測)。

### ③ 本当に効いているのは **索敵 12.5 タイル + 視線(LOS)** のほう

`DETECTION_RANGE` の判定は距離だけでなく **`hasLineOfSight` との AND**(`index.html:16532`)。
現行配置で s3→s4 の 41 歩のうち **3 マス**が「距離 12.5 未満 かつ 視線が通る」。
最初に見つかるのは **(38,20)**(= 玉座の間の口を横切る所)。
⭐ LOS が絡むので**間欠になる**(パーティの実位置が理想経路から数タイルずれるだけで変わる)。

### ④ ⛔ **案 2(s4 を西寄りへ動かす)は構造的に効かない**

南 (row ≥ 19) の候補 **104 タイル全部**で、護衛への最接近の上限が **8.06 タイル**。
choke は行き先ではなく **(38,20) 付近の玉座の間の口**で、南西へ下る道は
どこへ行こうとそこを通る。8 タイル超で済む候補は row 14〜15 の中央部だけで、
そこは**本道から 2〜3 マス**しか離れていない = 寄り道として成立しない
(既存条件「本道から 6 マス以上」を満たさない)。

### ⑤ ✅ 案 1(護衛を東へ)は効く。ただし **(48,\*) ではなく (51,20)/(51,22)**

`--places` で 5 配置を掃いた結果(seen = 距離 12.5 未満 かつ 視線が通るマス数):

| 護衛の配置 | 床か | s3→s4 で暴かれるマス | 最接近 | 最初に見つかる所 |
|---|---|---|---|---|
| **(46,20)/(46,22)** 現行 | 床/床 | **3 / 41** | 8.00 | (38,20) |
| (48,20)/(48,22) ← 依頼書の案 1 | ⛔ **(48,20) は壁** | 2 / 41 | 10.00 | (37,20) |
| (50,20)/(50,22) | ⛔ **(50,20) は壁** | 0 / 41 | 12.00 | — |
| (49,19)/(49,23) | ⛔ **(49,19) は壁** | 2 / 41 | 11.00 | (38,20) |
| **(51,20)/(51,22)** | ✅ 床/床 | ✅ **0 / 41** | 13.00 | — |

→ **(51,20)/(51,22) だけが「両方とも床」かつ「暴かれるマス 0」**。
  既存の制約「護衛は col 46 以東」(EV-9 のアンカー (40,21) から交戦距離 400px の外)は
  **さらに余裕をもって満たす**(11 タイル = 1056px)。

⚠ 依頼書が書いていた案 1 の座標 `(48,20)` は**岩**なので、そのまま実装すると
  スポーンが壊れるか無言でずれる。

## 決定(2026-08-22 ユーザー承認)— **案 1 修正版**

`N1_GUARD_SLOTS` を**東へ 5 列**動かす。⚠ 行番号は当てにせず**識別子で grep** すること。

```js
// before
const N1_GUARD_SLOTS = [[46, 20, "hobgoblin"], [46, 22, "hobgoblin"]];
// after
const N1_GUARD_SLOTS = [[51, 20, "hobgoblin"], [51, 22, "hobgoblin"]];
```

- ⛔ 本文の案 1 に書いた `(48,20)/(48,22)` は**採らない**(`(48,20)` は岩。⑤ の表)。
- ⛔ 案 2(s4 を動かす)は**採らない**(④ のとおり構造的に不可)。**s4 は `(24,23)` のまま**。
- ⛔ `DETECTION_RANGE` / `markVisitedAround` の半径 / heroAI の優先順は**触らない**(本文どおり)。

   **床/床 かつ「暴かれるマス 0 / 41」**であること。

### 実装窓が見ておくとよいこと

- ⚠ 護衛が玉座 `(49,21)` の**東**へ回り込む配置になる。数値上は問題ないが、
  **絵として不自然でないか**は実機で目視すること(玉座の背後を固める衛兵、と読める配置)。
- ⭐ ただし**玉座の間(泉の間)は rows 17-23 / cols 39-52**(`N1_GUARD_SLOTS` 直前のコメント)なので、
  `(51,20)/(51,22)` は**広間の中に収まっている**。壁際へ押し出されるわけではない。
- ⚠ `(51,*)` は部屋 rect `[2,17,24,55]` の内側(外周は row 2/24・col 17/55)。
  外周には掛かっていない。`isTileWall` は両方 false で実測済み。
