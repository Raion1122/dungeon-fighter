## 1. 目的

シナリオ2 のクリア率が **0% で床に張り付いて**いる。#8 は 80+40 走行の末に
「シナリオ2 は n1 で折れる。募集人数では動かない」と結論して宿題へ切り出し、
#16 は 8 ノードを 1 ノードへ畳んだが完走率は **0/3 のまま**だった。

⚠ **その 2 枚が置いていった前提は、今日の実測で 3 つとも崩れている**(§2-2)。
本チケットは「何を直せば動くのか」を**測って数値で出す**ところまでを担う。
⛔ **直しはしない。** 候補と効き目を出し、どれを採るかはユーザーが決める。

**ユーザー決定(2026-08-23)**:

| 問い | 決定 |
|---|---|
| チケットの形 | **調査のみ(#14 型)**。本番の振る舞いは変えず、測って候補を数値付きで出す |
| 測る範囲 | **シナリオ2 だけ**。沼 `lizard-swamp`(同じ ★★☆・#8 で未測定)は別チケットへ残す |
| 起案順 | #16 の宿題 1(n7 の間欠停止)より先に本件 |

⭐ 不採用にした案: 「調査 + 是正を 1 枚で」。**測る前に直す軸を決め打ちすることになる**ため。
今日の実測で最有力の軸(§2-3)は #8/#16 のどちらも想定していなかったものなので、
決め打ちは高い確率で外していた。

### 2-3. ⭐⭐⭐ 敗北の実体 — **パーティは全滅していない。主人公 1 人が死んでいる**

**25 走行すべてで `isPartyWiped()` は一度も真になっていない。**

下見の 12 走行(§2-5)でも **12/12 で仲間が 1 人以上生存**、うち **7 走行は仲間が完全に無傷**。

コードの根拠(実測で行を確認済み):

`if (ally.isHero) { gameOver = true; }` が 4 箇所(`:24522` / `:27128` / `:29648` / `:31518`)。
⇒ **どちらの隊列でも「主人公 1 人の死 = 即敗北」**。`isPartyWiped()` は事実上使われない。

構造上の理由(コードで確認・**推測ではない**):

## 4. STEP1 — 測定台 `tools/probe_s2_clear.js`(新規)

`tools/sweep_recruit_balance.js` を土台にする(酒場 → `departToScenario()` の本番導線。
⛔ index 直起動にすると人数が本番と変わる = #8 の実測)。**足すのは観測項目だけ**。

必ず出す列(§2 で「これが効く」と分かったもの):

1. **決着の 4 分類** — `clear` / `defeat`(全滅) / **`stall`** / `timeout`
   ⭐ `stall` は `localStorage["dragonfighters.debugReport"]` の
   `runs[].outcome === "aborted"` と `violations["stall"|"run-timeout"]` から採る(§2-9)。
   ⛔ 「上限秒数を超えた」だけで停滞と数えない(遅いだけの走行と混ざる)。
2. **主人公が死んだ瞬間に生きていた仲間の数** — `0` なら本当の全滅、`≧1` なら**主人公落ち**。
   ⭐ これが §2-3 の主張を毎走行で機械検査する列になる。
3. **主人公の被ダメージ / パーティ総被ダメージ** の比(0.5〜1 秒ポーリングの差分の総和で近似)。
4. **同時交戦の最大数**(`encounterEnemyIndices.length` のピーク)と、その時の敵の名前。
5. **入場 Lv / 主人公 maxHP / 仲間の Lv**(母集団の記録)。
6. 終了時の残敵数と、**ボスを倒したか**。

⚠ 裸の識別子で読む(`window.<名>` では読めない = classic script 直下の `let`)。
⚠ ポーリングを短くしすぎない(150ms の `evaluate` は測定対象そのものを遅くする = P9 の教訓)。
⚠ `path.resolve` 必須。ROOT をスラッシュのまま持つと `path.join` の返す区切りと
`startsWith` が一致せず **全ファイル 404**(本窓の下見で実際に踏んだ)。
