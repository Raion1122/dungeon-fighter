# スプライト生成の縮尺ルール(歩行 / 攻撃のサイズ食い違い対策)

生成 AI(ChatGPT / DALL-E など)に 2D ゲーム用のキャラスプライトを描かせるとき、
**歩行シートと攻撃シートで被写体のズーム(大きさ)が食い違う**という失敗がある。
ゲーム中で攻撃モーションに切り替わった瞬間、キャラが一回り伸びたり縮んだりして見える。

このドキュメントは、その対策として**実測で効くと分かった書き方**と、
**効かないと分かった書き方**をまとめたもの。他プロジェクト・他スキルへ移植できるよう、
特定のツールや変数名に依存しない形で書いてある。

---

## 1. なぜ「歩きと攻撃で同じ大きさで描いて」と書くだけでは効かないのか

**実際に書いてあって、実際に失敗している。**

ある実プロジェクトの共通仕様テンプレには、以下の一文が最重要マーク付きで入っていた。

> キャラ本体のサイズは全フレーム統一(歩きと攻撃で同じ大きさ、これが最重要)

この文言がある状態で出荷された 72 シートを実測した結果:

| 指標 | 値 |
|---|---|
| 体高(足裏〜頭頂)の walk→attack 変化率 median | **-2.7%** |
| ズレ 5% 超(体感で分かる) | **22 / 72 シート** |
| ズレ 10% 超 | **12 / 72 シート** |
| 最小 / 最大 | **-33.3% / +22.6%** |

つまり **強調を重ねる方向の改善は無効**。「もっと強く書く」「大文字にする」
「最重要と繰り返す」は、この失敗を一度も減らしていない。

**根本原因は文言ではなく構造**にある:

- 歩行と攻撃は**別々の画像として出力**させる(1 枚に混ぜるとモデルシート化事故が起きるため)
- 別々に描かせる以上、**生成器には「前の絵と同じ大きさか」を検証する手段が無い**
- 検証手段が無い指示は、どれだけ強調しても守られない

→ **直すべきは「強調」ではなく「検証可能な形に指示を作り替えること」**。

なお、同じ実測で **足元(接地線)の位置ズレは median 0px** だった。
つまり位置は既に合っていて、**純粋にスケールだけの問題**である。
この良い性質は偶然に任せず、テンプレに明記して維持する(下記 手 3)。

---

## 2. 効く 3 手

### 手 1(本命・コストゼロ): 基準コマを統一する

**歩行の 1 コマ目と攻撃の 1 コマ目を、完全に同一の「立ち」ポーズにする。**

```
▼歩行(6フレ)
1: 立ち(基準ポーズ ← 攻撃の1コマ目と完全に同一)
2: 右足前
...

▼攻撃(6フレ)
1: 立ち(基準ポーズ ← 歩行の1コマ目と完全に同一)
2: 構え・振り上げ
...
```

**なぜ効くか**:

- 2 枚の 1 コマ目が同じポーズなら、その差は**純粋なズーム差**になる。
  パイプライン側が `体高(歩行の1コマ目) ÷ 体高(攻撃の1コマ目)` で
  **補正倍率をそのまま実測できる**。
- 従来のように「歩行 1 = 立ち / 攻撃 1 = 構え」だと、ポーズ差(前傾・膝の曲げ・
  武器の持ち上げ)がスケール差に**交絡**する。実測ではこのポーズ由来のノイズ床が
  約 3.2% あり、体感閾値(±5〜6%)に対して無視できない。1 コマ目を揃えると
  このノイズ床ごと消える。
- 生成器にとっても「前に描いた絵をそのまま置いてから 2 コマ目以降を動かす」は
  **同一チャット内で実行可能な手順**であり、検証不能な「同じ大きさで」より守りやすい。

**コストゼロである点が重要**: フレーム数も画像枚数も変わらないので、
既存のバッチ運用に一切影響しない。攻撃の「構え」が 2 コマ目に移るだけ。

### 手 2: フレーミングを % で指定する

1 コマ分の矩形(フレーム)の高さを 100% として、**数値で**指定する。

```
- 足裏(接地線) = フレームの下端から 5% の高さ
- 頭頂(兜・角・耳・髪を含む。武器は含めない) = フレームの上端から 30% の位置
- したがって 足裏〜頭頂(=身長) = フレーム高の 65%
- この3つの数値は歩行と攻撃の両方で同じにすること
```

**注意点 2 つ**:

1. **数値そのものに意味はない。2 枚で同じであることだけが重要。**
   5 / 30 / 65 は「キャラの上に武器を振り上げる余地を残しつつ、十分大きく描ける」
   配分の一例にすぎない。プロジェクトの絵柄に合わせて変えてよいが、
   **変えるなら歩行・攻撃の両方を同時に変える**。
2. **武器・振り上げた腕・エフェクト・はためくマント・尻尾は 65% の計算に含めない**と
   明記する。含めてよいと解釈されると、生成器は**キャラ本体を縮めて枠に収めにくる**。
   これは「攻撃コマだけ小さくなる」という、まさに直したい失敗そのものを誘発する。

### 手 3: 足元(接地線)を明文化する

```
- 足裏(接地線)の高さは全コマ・全モーションで共通にする
  (踏み込みで沈む等の上下動は数ピクセル以内に留める)
```

前述のとおり、足元は**既に合っている**(実測 median 0px)。
これは指示していないのに得られている良い性質なので、
**偶然に任せず明文化して維持する**。手 2 の「下端から 5%」と併せて書けば足りる。

## 3. 効かないと確定済みの手(書かないこと)

| 書き方 | なぜ効かないか |
|---|---|
| **ピクセル数の指定**(「キャラは 96px で」) | 生成器は出力解像度を制御していない。指定しても守れない |
| **「前回と同じ大きさで」** | 参照画像が無い(別画像として出力させている)ので、生成側に検証手段が無い |
| **「大きく堂々と描いて」** | 方向だけの形容で、量の指示になっていない。どれだけ大きいかが決まらない |
| **「同じ大きさ、これが最重要」と強調を重ねる** | 上記 1. のとおり、この文言がある状態で -33% 〜 +23% が出ている |

いずれも**追加してはいけない**。効かないだけでなく、プロンプトを長くして
他の有効な指示の相対的な重みを下げる。

---

## 4. 採用しなかった案とその理由

**「2 行 × 6 コマ(上段=歩行 / 下段=攻撃)を 1 枚のキャンバスに描かせる」**

- 物理的には最も確実。同じキャンバスに描く以上、縮尺は必ず揃う。
- **それでも採用しない**理由: 1 枚に複数モーションを描かせると、生成器が
  「キャラクター設定資料(モデルシート)」として解釈し、ポーズ集や
  三面図のような**ゲームに使えない絵**を返す事故が起きた実績がある。
  この事故を避けるために「1 モーション = 1 枚」の運用が確立された経緯がある。
- **将来の逃げ道**: 手 1 + 手 2 で足りない(依然 5% 超が出る)場合に限り、
  **1 キャラだけ**で 2 行 1 枚を試す。全面採用の前に必ず 1 キャラで検証すること。

**「出力後に補正倍率をかけて機械的に揃える」(パイプライン側の全面補正)**

- 対症療法としては有効で、実際に出荷済みアセットはこれで救済した。
- しかし**全面採用は不可**。補正倍率は defect の逆数なので、
  **一番ひどい絵に一番荒い拡大縮小がかかる**(-33% の絵に 1.5 倍のリサンプル)。
  素材側を直す(= このドキュメントの手 1〜3)方が先。

## 5. 検証方法

**閾値**: 体高(足裏〜頭頂)の walk→attack 変化率が **±5%** を超えたら WARN。
体感で「伸縮した」と気づくのは概ね ±5〜6% から。

**測り方の要点**(自前で実装する場合):

- 物差しは **bbox 高ではなく体高**を使う。攻撃コマは武器を振り上げるので
  bbox 高は武器で汚染される。同様に**肩幅・胴の対角も使ってはいけない**
  (攻撃で腕を広げるぶん膨らむ)。
- 頭頂の定義: alpha > 64 の画素について、**行の不透明画素数が最大値の 25% 以上**を
  満たす最上行。こうすると武器・角・触角のような細い突起が頭頂に数えられない。
- 足元の定義: bbox の下端。
- フレーム群の代表値は **median**(踏み込みで沈むコマ等の外れ値に引きずられない)。
- 位置ズレ(足元の x 差)も併せて出すと、「位置の問題か縮尺の問題か」を切り分けられる。

**このプロジェクトでの実行方法**:

```bash
py tools/check_attack_scale.py                # 全シート走査してサマリ表
py tools/check_attack_scale.py --threshold 5  # WARN 閾値(%) 変更 (既定 5.0)
py tools/check_attack_scale.py --fail-on-warn # WARN が 1 件でもあれば exit 1 (回帰検知)
py tools/check_attack_scale.py --json         # 機械可読出力 (自動検証用)
```

**現在のベースライン(2026-07-29)**:

```
total=76  compared=71  OK=71  WARN(|d|>5%)=0  |d|>10%=0  placeholder=4  skip=1
median delta = -1.35%   min = -5.00%   max = +1.92%
```

出荷済みアセットは全て WARN 0 まで解消済み。ただしそれは**パイプライン側の補正**であり、
**素材そのもののズレは残っている**。このドキュメントの手 1〜3 は
**これから作る素材で再発させない**ためのもの。

**注意**: このドキュメントに沿ってテンプレを改訂しても、上記の数値は**動かない**
(既存アセットは 1 バイトも変わらないため)。動いたら何かを壊している。
効果の実証には**新しい素材を 1 キャラ生成して測る**必要がある。

## 6. 移植チェックリスト

他プロジェクト / 他スキルへ持ち込むときは、以下が満たされているか確認する。

- [ ] 歩行の 1 コマ目と攻撃の 1 コマ目が、**同一の立ちポーズ**と明記されている
- [ ] 攻撃の「構え」が **2 コマ目から**始まると明記されている
- [ ] 足裏 / 頭頂 / 身長が **フレーム高に対する %** で指定されている
- [ ] その % が **歩行と攻撃で同じ**と明記されている
- [ ] **武器・腕・エフェクトを身長の計算に含めない**と明記されている
- [ ] **足元(接地線)を全モーションで同じ高さに置く**と明記されている
- [ ] ピクセル数指定 / 「前回と同じ」/ 方向だけの形容 が**書かれていない**
- [ ] 「同じ大きさ、最重要」的な**強調頼みの文言が残っていない**(構造に置き換わっている)
