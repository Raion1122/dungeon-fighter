## 第1ラウンド：設計

【レンツ】まず全員の前提を壊しておく。**「隊商が魔物に襲われる戦闘」は作らなくていい。もうある。**
7.9-3 で馬車も街道テクスチャもウェーブ状態機械も敗北条件も出荷済みだ(実測1・2)。
今回の新規性は戦闘の中身じゃなく、**「ワールドマップを歩いている最中に、それが割り込んでくる」という導線**の一点。
そこを取り違えると、既にあるものを二度作る一番間抜けな工数の使い方になる。

【ガイウス】いい指摘だ。だが体験としては別物だぞ。ポドルプラザで受注する隊商護衛は「仕事」だ。
今回は「**通りすがりに悲鳴を聞いた**」——Gold Box でいうランダムエンカウントの、いちばん美味しいところだ。
同じ馬車でも、依頼書を持っているかいないかで意味がまるで違う。仕掛けは流用でいい、**枠付けだけは絶対に変える**。

【レンツ】枠付けは同意する。で、配管だ。world.html から戦闘へ入る口は既にある(実測4)。
`currentScenario` + `generatedScenario` を書いて `location.href = "index.html"`。それだけだ。
ただし **`currentScenario` を上書きしてはいけない**。上書きすると襲撃から戻ったあと、
本来のクエスト地へ入場したときに **襲撃シナリオが起動する**。酒場が出発時に焼いた値を誰も戻さないからだ。

【レンツ】だから専用キーを 1 本立てる。`dragonfighters.roadBattle` に襲撃のペイロードを入れ、
**index.html が最優先で読んで、読んだら消す**。#47 の `roadBoon` とまったく同じ型だ
(world は書くだけ / index が消す)。これなら酒場が焼いた `currentScenario` も `generatedScenario` も 1 バイトも汚れない。

【ノエル】待って。**戻ってきたとき、どこに立ってるの?**

【レンツ】……それだ。実測5。world.html は主人公位置を保存していない。`spawnFor` は
`via==="dungeon"` のとき `SITES[scenarioId]`、無ければ **`"phlan"`** を返す。
つまり素直に作ると「**街道で戦ったら港町フランに帰らされる**」。これは仕様バグじゃなくて体験の破壊だ。

【ノエル】それ、私が実機で最初に踏むやつ。しかも「バグだ」って気づかないの。
「あれ、なんで街に戻ってるんだろう…まあいいか」で終わる。**いちばん質の悪い壊れ方**。

【レンツ】直し方は `heroNodeId` の初期化に 1 段挟むだけ。`roadReturn` があればそれを使い、無ければ従来どおり `spawnFor`。
#23 が確立した型そのまま——「行き先はページの静的な属性ではなく、状態の関数」。
⚠ ただし **消すのに `removeItem` を使えない**(実測6)。world.html の配信バイトの `removeItem` は
1 件に固定されている。空文字で上書きして消費する。気持ち悪いが、番人を緩めるよりずっと安い。

## 第2ラウンド：肉付けと衝突

【ミサキ】絵の話。街道の戦闘に **専用マップは絶対に要る**。今の `caravan-road` は
テクスチャ 2 枚を敷いているだけで、1 枚絵は 1 枚も無い(実測11)。
森のアジト `n7big` みたいに、**codex が描いた街道の卓上マップの上で戦う**画にしたい。
横倒しの荷車、散らばった積荷、路肩の茂み、逃げ遅れた荷役。あれが出た瞬間に「事件だ」って分かる。

【レンツ】そこで技術的な衝突が 1 個ある。`caravan-road` は **FIELD テーマ**で、歩ける帯が
**row 13-15 の 3 行しかない**(実測11)。1 枚絵の卓上マップは 26 行使う。**両立しない。**

【ミサキ】じゃあ帯を広げれば……

【レンツ】⛔ それは駄目だ。屋外の帯描画は隊商護衛・ワールド地平線ビュー・散布物・霞まで
全部がその 3 行を前提に組んである。触ったら 7.9-3 が丸ごと壊れる。

【ガイウス】いや、答えは既に出ている。**`n7big` がまさにその答えだ。**
あれは「屋外・昼・空が見える」マップだが、**FIELD 描画ではなく部屋絵の経路**で描かれている(実測10)。
`outdoor: true` を持っていて、入った瞬間に地形全体が見える。
つまり「屋外に見える卓上マップ」の作り方はもう確立済みで、**帯描画には一切触らない**。

【ミサキ】……つまり私が欲しかったものは、既にレシピがあると。

【レンツ】ある。`tools/make_grid_map.py` の台帳に 1 行足して焼くだけだ。
`blocked` マスクを 26 行 x N 列で手書きするのが唯一の重い作業。森のアジトで一度通した道だ。

【ガイウス】次は体験設計だ。**断れなければならない。**
「助けに入る」しか無いランダムイベントは、イベントじゃなくて通行料だ。
街道の出来事 6 件はすべて「関わる / 関わらない」の二択で、片方が判定なし。
今回もその形を厳守する——**「見捨てて回り込む」が判定なしの枝**。

【レンツ】⭐ それは体験の話であると同時に、**golden を守る唯一の形**でもある(実測9)。
既存ドライバ 3 本は `filter(x => !x.check)[0]` を機械的に押す。
もし「助けに入る」が判定なし側に来たら、**テストが片っ端から戦闘へ落ちる**。
ガイウスの美学と、番人の要求が、たまたま完全に一致した。

【ガイウス】たまたまではない。判定を要求する側が「関わる」なのは D&D の作法だ。

【ノエル】じゃあ「助ける」側の判定は何を決めるの? 成功したら助けられて、失敗したら助けられない?
それだと **失敗した瞬間に戦闘が消える**。d20 で 1 が出たら「今日は事件がありませんでした」。最悪の手触り。

【ガイウス】判定は **戦闘に入るかどうか**ではなく、**どう入るか**を決めるべきだ。
成功 = 気づかれずに回り込んで **奇襲**。失敗 = 正面から飛び込んで**乱戦**。どちらも戦う。

【レンツ】それなら #47 の「備え」がそのまま使える。`applyRoadVigilance` = 敵の初手を 1 ターン潰す。
**配線先が既に通っている**。新しい戦闘機構はゼロだ。

【ノエル】もう 1 個ある。**HP はどうなるの?** 襲撃で削られたまま本命のダンジョンに入るなら、
そこは相当きつい。逆にリセットされるなら、この戦闘は **ノーリスクのボーナスステージ**になって緊張がゼロ。

【ガイウス】ノーリスクは論外だ。「関わらず立ち去る」が選択肢としてある以上、
関わる側にリスクが無ければ、**選択が選択でなくなる**。

【レンツ】ただし持ち越しは配管が重い。#47 の判断を思い出せ——あのときも
「失敗 = 痛手」を検討して **恵みだけ**に落とした。理由は「関わらず立ち去るが常に最適解になる圧が出る」。
今回は逆で、**リスクが無いと関わるが常に最適解**になる。同じ罠の裏返しだ。

【ノエル】折衷案。**戦闘そのものが報酬と罰を兼ねる**のはどう?
襲撃は「本命のダンジョンより 1 段軽い」戦闘にして、HP は持ち越さない。
代わりに **馬車が壊れたら報酬が消える**。プレイヤーが失うのは HP ではなく「助けられたはずの隊商」。

【ガイウス】……それは D&D として正しい。**罰は数値ではなく結末で与える**。悪くない。

【レンツ】実装も安い。`escortWagonLost()` は既にある。⛔ ただし **gameOver は立てない**。
7.9-3 は「馬車全損 = 敗北」だが、通りすがりの襲撃でそれをやると
「本命のクエストに行く途中で全滅扱い」になる。**そこは 7.9-3 と分岐させる**。

【ノエル】そこ、iOS 実機で一番効くところだから絶対にそうして。街道で負けて宿屋に戻されたら、
プレイヤーは二度と「助けに入る」を押さない。

## 第3ラウンド：合意

【レンツ】発火の置き場所を最後に詰める。⛔ **`EVENTS` に 7 件目として足すのは駄目だ**(実測7)。
`measureChoice` が固定種で 1 件引いて (3f) が判定つきの枝を押す。表に 1 件足すと引きが動き、
**押される先が襲撃に変わった瞬間に golden が index.html へ落ちる**。
⇒ 襲撃は **EVENTS とは別の表 + 別の振り**にする。既存 6 件の分布は 1 ビットも動かない。

【ガイウス】頻度も別にできるということだな。街道の与太話が 5〜20% で出るのに対し、
**襲撃は「滅多に無いが忘れられない」**——横断 1 回あたり 1 割を切るくらいでいい。

【ノエル】party の実体があるときだけ出して。ワールドマップは受注なしでも歩けるから、
`partyMembers` が無いのに戦闘へ飛ばすと、**index.html が勝手に別編成を組む**。
そこは黙って壊れるやつだから、素直に「編成が無いなら出さない」でいい。

【レンツ】段取りはこうだ。マップは codex の手が空くのを待つ必要があるので **先に発注**し、
その間にこちらは既存の絵で導線を通す。マップが届いたら差し替える。**2 チケットに割る。**

【ミサキ】絵が最後でも、導線が先に通っていれば「どこに何を描くべきか」が確定した状態で発注できる。むしろ順序として正しい。

【ガイウス】異論なし。これは D&D だ。街道は安全ではない。

# 📋 開発計画書：街道の襲撃

## 1. 目的

ワールドマップ横断中に、**まれに**「隊商が魔物に襲われている現場」に出くわし、
**助けに入る / 見捨てて回り込む**を選べるようにする。助けに入れば、その場で 1 戦して街道へ戻る。

## 2. スコープ分割(2 チケット)

| チケット | 内容 | 依存 |
|---|---|---|
| **#51 街道の襲撃(導線と戦闘)** | 別表 + 別振りの襲撃イベント / 戦闘への往復 / 帰還位置の保全 / 報酬 / 撤退スイッチ / 検証ドライバ | 既存アセットで完結。codex 待ちなし |
| **#52 街道の卓上マップ(codex 発注)** | `dnd-map-maker` へ発注 → 焼き付け → `blocked` マスク → `ROOM_PAINTINGS_DEF` + `mapDef` 登録 → #51 の襲撃が使うマップを差し替え | codex 納品待ち。**発注は #51 の着手と同時に出す** |

## 3. アーキテクチャ(流用と新規)

### 流用するもの(新規実装ゼロ)
- 馬車 `ENEMY_TYPES.caravanWagon` / `spawnWagon()` / `wagonSpawns`
- ウェーブ状態機械 `spawnWave` / `escortWaveList()` / `escortWagonLost()`
- ad-hoc シナリオの受け口(`generatedScenario` を読む枝・`waves` / `wagonSpawns` は素通し済)
- 奇襲 = #47 の `applyRoadVigilance`(敵の初手を 1 ターン潰す)
- 器 = `#worldEventBox`(`ROAD_EVENTS.open` / `showResult`)
- 昼視界 = `IS_FIELD_THEME` 連動の `__daylight`(または `outdoor: true` の部屋絵)

### 新規に足すもの(最小)
1. `js/road-events.js` — **`AMBUSH` 表 1 件 + 引き**(⛔ `EVENTS` には足さない)
2. `world.html` — 襲撃の振り 1 本 / 戦闘ペイロードの書き出し / 帰還位置の保全
3. `index.html` — `roadBattle` の消費(読んだら消す)と ad-hoc シナリオへの流し込み / 馬車全損時に **gameOver を立てない**分岐
4. `tools/verify_road_ambush.js` — 新規ドライバ

### 触らないと決めたもの
- ⛔ `js/world-map.js`(`spawnFor` / `NODES` / `EDGES` / `SITES` — sha1 で固定されている)
- ⛔ `EVENTS` の 6 件と `RATE`(既存 golden の引きを 1 ビットも動かさない)
- ⛔ `tavern.html` の `caravan-escort` 系統(7.9-3 は無傷)
- ⛔ 屋外の帯描画(row 13-15)と `FIELD_THEMES`

## 4. 確定した設計判断(理由つき)

| 判断 | 理由 |
|---|---|
| **襲撃は `EVENTS` の 7 件目にしない**。別表・別振り | `measureChoice` の固定種の引きが動き、(3f) が襲撃の判定枝を押して golden が index.html へ落ちる |
| **「見捨てて回り込む」が判定なしの枝** | 既存 golden 3 本が `filter(x => !x.check)[0]` を押す。ここを逆にすると全部が戦闘へ落ちる。かつ D&D の作法としても正しい |
| **判定は「戦うか」ではなく「どう戦うか」を決める** | 失敗で戦闘が消えると「1 を出したら事件が起きない」最悪の手触りになる。成功=奇襲 / 失敗=乱戦 |
| **`currentScenario` / `generatedScenario` を上書きしない**。専用キー `roadBattle` | 上書きすると襲撃から戻った後、本命のクエスト地で襲撃シナリオが起動する |
| **帰還位置を保全する**。無ければ港町フランへ飛ばされる | `spawnFor` は未知の scenarioId に対し `"phlan"` を返す |
| **world.html で `removeItem` を増やさない**。消費は空文字上書き | `verify_road_events` (2c) が配信バイトの `removeItem` を 1 件に固定している |
| **馬車全損でも `gameOver` を立てない** | 7.9-3 は「馬車全損=敗北」だが、通りすがりの襲撃でそれをやると本命クエストへ行く途中で全滅扱いになる |
| **`partyMembers` が無いときは発火しない** | 無いまま戦闘へ飛ばすと index.html が別編成を組み、黙って壊れる |

## 5. codex 発注(#52)の骨子

- スキル **`codex-map-request`** の 4 段(発注 → 受入 → 焼き付け → MASK)をそのまま通す
- 前例 = `assets/room_bandits-forest_n7_map.jpg`(`tools/make_grid_map.py --name bandit-hideout`)
- 発注時に決める 5 つ: 用途=屋外の卓上バトルマップ / 貼り先の変数名 / **1 マス 48px** / 歩ける床の割合 / 捨てる外周
- ⛔ マス数は発注する値ではなく、`--fit` で測って出てくる値
- 画題: 昼の街道。停まった荷車、散らばった積荷、路肩の茂みと石積み、荷役の避難先。
  **街道は東西に切れ目なく通す**(経路探索の唯一の道)

## 6. iOS 検証項目

1. `#worldEventBox` が 390x844 に収まる(既存 (1d) と同じ物差し)
2. 「助けに入る」→ 戦闘 → 帰還までのページ遷移で音が切れないか
3. 帰還後、主人公が**襲撃地点に立っている**こと(港町ではない)
4. 帰還後、受注中の依頼の目印が残っていること
5. 襲撃から戻ってそのままクエスト地へ入場したとき、**本来のシナリオ**が起動すること
