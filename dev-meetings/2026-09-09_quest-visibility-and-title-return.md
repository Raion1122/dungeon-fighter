## 第1ラウンド：ブレスト

**【ガイウス】** まず枠付けをさせてくれ。この 3 件は一見バラバラだが、根は 1 つだ。**「自分が今どの物語の途中にいるのか」をゲームが答えてくれない。** Gold Box ではな、パーティ画面を開けば必ず「今受けている依頼」が journal に載っていた。あれは親切心じゃない、冒険者が冒険者である証明なんだ。だから私の方向性は **「依頼書(クエストログ)を持ち物にする」**。受注した時点で羊皮紙が 1 枚パーティの手に渡り、それを開けば依頼人・目的地・報酬が読める。「！」も名前の常時表示も、その 1 枚から派生させる。

**【レンツ】** 気持ちは分かるが、実装の前提を 1 つ潰しておく。ガイウス、あんたは今「受注した時点で」と言ったな。**受注状態はどこにも保存されていない。** 実測 9 番だ。`prepScenario` は `tavern.html` の中の**ただの JS 変数**で、6220 行で宣言されて 7651 行で null に戻る。ページを 1 枚またいだ瞬間に消える。

**【ガイウス】** ……待て。では今、廃坑へ向かって世界地図を歩いている間、ゲームは何を握っているんだ。

**【レンツ】** `questDest` ただ 1 つ。**シナリオ id の文字列 1 個だけ**だ。「ゴブリンの巣窟」という名前は握っていない。しかも sessionStorage だからタブを閉じたら消えるし、実測 1 番のとおり**世界地図を経由する枝でしか書かれない**。だから私の方向性は **「受注状態を 1 つの器に正しく持たせる」**。名前も、依頼人も、受注日も入る器を 1 つ作って、`questDest` はそのまま残す。地味だが、これが無いと他の 2 件が空中に建つ。

**【ミサキ】** 私はもっと単純に、**画面で気持ちよくしたい**。世界地図って今、羊皮紙の立て札が 7 枚並んでるだけなんですよ。受注してても札の見た目が 1px も変わらない。ここ、**目的地の札だけ脈動させる**べきです。赤い封蝋がぽとりと落ちて、そこから細い光の線が主人公の駒まで伸びる。「！」なんて記号じゃなくて、**依頼の封書が目的地で待ってる**という絵にしたい。`#worldTitle` の小さい行にも「廃坑 — ゴブリンの巣窟」って出せば、地図を開いた瞬間に自分の物語が分かる。

**【ノエル】** 3 件目、私に言わせてください。**これ、QoL じゃなくてバグ寄りです。** 慶彦さんは「スマホで戻れない」と言った。私も実機で確かめました。戻れないのは仕様が不親切だからじゃない、**`title.html` が `location.replace` で自分を履歴から消しているから**です(実測 12 番)。つまり iPhone の戻るジェスチャを何回スワイプしても、タイトルは**もう存在しない**。プレイヤーからしたら「詰んだ」に見える。だから私の方向性は **「どのページからも開ける共通メニューを 1 つ置く」**。そこに「旅の記録」も「タイトルへ戻る」も入れる。片手の親指が届く位置に、1 個だけ。

# 🎲 実装候補（方向性を選んでください）

## 候補①：最小の 3 点留め — 印・小行・戻るボタン

- **ジャンル**: QoL（最小手数）
- **狙い**: 3 つの穴を、既にある器の中だけで塞ぐ
- **中身**: 世界地図の目的地の札に印を出す(`questDest` をそのまま使う) / `#worldTitle` の `<small>` 行に地名を出す / `title.html` へ戻るボタンを街と世界地図に 1 個ずつ
- **ざっくり規模**: 小
- **既存流用度**: 高（新しい保存キーを 1 つも作らない）
- **iOS Safari**: クリア
- **弱点**: **クエスト名が出せない**。`questDest` はシナリオ id しか持たないので、出せるのは「廃坑」まで。「ゴブリンの巣窟」は原理的に出ない(実測 8/10 番)。要望 2 が半分しか満たせない
- **推し**: ノエル ／ **慎重**: ガイウス

## 候補②：受注状態の器を 1 つ作る（土台先行）

- **ジャンル**: データ基盤 + QoL
- **狙い**: 「今受けている依頼」を名前ごと 1 つの器に持たせ、そのうえで 3 件を全部満たす
- **中身**: 受注時に `place` / `title` / シナリオ id を持つ器を localStorage へ 1 つ焼く(⛔ 書くのは酒場、`world.html` は**読むだけ**) / 世界地図の印と `<small>` 行はその器から引く / 戻るボタンも同時に足す
- **ざっくり規模**: 中
- **既存流用度**: 中（`questDest` は 1 バイトも触らずに残す = 既存 golden が全部生きる）
- **iOS Safari**: クリア
- **弱点**: 新しい保存キーが 1 つ増える。`DFSlots` のスロット保存にも自動で乗る(prefix が同じなら)ので、そこの確認が要る
- **推し**: レンツ、ガイウス ／ **慎重**: ノエル（「器を作って画面を作らないのは中途半端に見える」）

## 候補③：依頼の封蝋 — 地図を演出で語らせる

- **ジャンル**: 演出強化
- **狙い**: 記号ではなく絵で「ここが目的地だ」と分からせる
- **中身**: 目的地の札に赤い封蝋を落とし、脈動させる / 未受注の札との明度差を付ける / `<small>` 行も羊皮紙のインク色で組む
- **ざっくり規模**: 中
- **既存流用度**: 中（`.worldSign` のトンマナをそのまま使う）
- **iOS Safari**: 要注意（脈動は 1 要素なら通る。⛔ 主人公まで伸びる光の線は歩行アニメと衝突するので会議で却下済み）
- **弱点**: **要望 3(戻る導線)を 1 mm も解決しない**。単独では慶彦さんの依頼の 1/3 しか埋まらない
- **推し**: ミサキ ／ **慎重**: レンツ、ノエル

## 候補④：共通メニューを 1 つ置く

- **ジャンル**: UX 基盤
- **狙い**: どのページからも開ける小さなメニューを作り、3 件をそこへ集約する
- **中身**: 街・世界地図・酒場の隅に固定ボタンを 1 個 / 開くと「受注中の依頼」「タイトルへ戻る」が並ぶ / 将来は journal もここへ足す
- **ざっくり規模**: 大
- **既存流用度**: 低（4 ページに同じものを載せるので同期コストが出る）
- **iOS Safari**: 要注意（⛔ `#worldTitle` の中には置けない。`pointer-events:none` を外すと札 7 枚のクリックが死ぬ）
- **弱点**: 触るファイルが `index.html` / `tavern.html` にも及ぶので changelog 強制の対象になり、母集団の golden も広く動く。**#63 が着地する前にやると並走事故の面が広い**
- **推し**: ノエル ／ **慎重**: レンツ、ミサキ

## 第1ラウンド：設計

**【レンツ】** 器から決める。**キーは `dragonfighters.activeQuest` 1 本、localStorage、JSON 1 個**だ。中身はこれだけにする。

```
{"id":"goblin-mine","place":"廃坑","title":"ゴブリンの巣窟","at":1757400000000}
```

依頼人も報酬も入れない。ノエルが第1段で言ったとおり、入れると表示画面が要る。**prefix が `dragonfighters.` なので `DFSlots` のスロット保存に自動で乗る**(実測 13 番の `LIVE_PREFIX`)。`KEEP` に入れなければスロットごとに独立する。それが正しい。

**【ガイウス】** 書くのはいつだ。

**【レンツ】** 酒場の受注 1 箇所。`openPrep(sc)` が `prepScenario = sc` を代入する行の隣だ(`tavern.html:6236`)。**消すのは `consumeResult()` の中 1 箇所**(`tavern.html:5465`)。ここが要点でな、実測 23 番で **`lastResult` はクリアでも敗北でも撤退でも必ず書かれる**ことを確かめた。だから消す場所を 1 つに畳める。**書き 1 箇所・消し 1 箇所**。これ以上増やさない。

**【ノエル】** 待ってください。**印は器から出すんですか?**

**【レンツ】** いや。**印は `questDest` から出す。器からは出さない。** これが今日いちばん大事な決定だ。

**【ミサキ】** なんでですか? 器の方が情報が多いのに。

**【レンツ】** 器は localStorage、`questDest` は sessionStorage だ。**タブを閉じて開き直すと器だけ残って `questDest` が消える。** そのとき器で印を出すと、**印が出ているのに札を押しても入れない**。実測 2 番のとおり入場は `questDest` の一致で決まる(`world.html:1086`)から、入場条件を変えない限りこうなる。

**【ノエル】** ……それ、プレイヤーからしたら完全にバグですね。「マークが付いてる所へ行ったのに何も起きない」。

**【レンツ】** そうだ。だから役割を分ける。**印が出る ⟺ 入れる** を `questDest` 1 本で保証し、**器は名前を出すためだけに使う**。器があってもなくても、印の挙動は今日と同じ条件で決まる。

# 📋 開発計画書：受注の器 + 封蝋 + 記憶へ戻る道

## 概要

受注中の依頼を保持する器を localStorage に 1 つ作り、そこから「地名 — 依頼名」を 3 面に常時表示する。世界地図の目的地の札には封蝋の印を出して一目で分かるようにする。あわせて、街と世界地図からキャラ選択画面へ戻る道を 1 本ずつ通す。

## 実装スコープ

**作るもの**

- 受注中の器 `dragonfighters.activeQuest`(localStorage / JSON 1 個)
- 常時表示 3 面: 世界地図 `#worldTitle small` / 街 `#townTitle` / 酒場
- 世界地図の封蝋 `.worldSeal`(`questDest` 由来)
- 「はじめの画面へ」ボタン 2 面: 街 `#townHud` / 世界地図の固定ボタン

**作らないもの**

- ⛔ クエストログ画面 / journal(ガイウスの案は次の議題へ)
- ⛔ 依頼人・報酬・受注日の保持(器には入れない)
- ⛔ 潜行中(`index.html`)の常時表示と戻るボタン
- ⛔ 主人公まで伸びる光の線(会議で却下。歩行アニメと衝突する)
- ⛔ 生成クエスト(掲示板 / 闇市)への封蝋(実測 3 番。世界地図を通らないので原理的に不要)

## 流用する既存システム

- **`questDest`**: 封蝋の出し分けにそのまま使う。⛔ 1 バイトも変えない
- **`DFSlots`**: 器は prefix が同じなのでスロット保存に自動で乗る。⛔ `js/save-slots.js` は触らない
- **`consumeResult()`**: 器を消す 1 箇所として相乗りする。新しい sessionStorage キーを作らない
- **`#townHud`**: 街の戻るボタンは既存のボタン生成に 1 個足すだけ
- **`.worldSign`**: 封蝋はこの兄弟要素として重ねる

## 新規実装

| 項目 | 内容 |
|---|---|
| 器 | `dragonfighters.activeQuest` = `{id, place, title, at}`。書き 1 箇所(受注時)・消し 1 箇所(帰還時) |
| 常時表示 | 3 面。⭐ **行数を増やさず既存の 1 行を差し替える**(`insets()` を動かさないため) |
| 封蝋 | `.worldSeal`。`transform: scale()` + `opacity` の 2 秒周期。⛔ `box-shadow` アニメ禁止 |
| 戻る道 | `location.href = "title.html"` の 1 行。⛔ `replace` にしない(履歴を残す) |

## 素材調達

**なし。** 封蝋は CSS のみで描く。画像も音も追加しない。

## iOS Safari 検証項目

- 封蝋の脈動が 1 要素だけで、歩行中も駒が跳ねないこと
- 戻るボタンが 390px 縦持ちで親指の届く位置にあり、札や駒のタップを奪わないこと
- `#worldTitle` の文言差し替えで帯の高さが変わらず、札が帯の下に潜らないこと
- 器が無い(未受注)状態でも 3 面が今日と同じ見た目であること

## 実装ステップ（順序）

1. **器**を作る(書き 1 箇所・消し 1 箇所)。表示はまだ作らない
2. **常時表示 3 面**を器から引く
3. **封蝋**を `questDest` から出す
4. **戻るボタン**を街と世界地図に 1 個ずつ

⭐ 1 → 2 は必須の順序。3 と 4 は互いに独立で、どちらを先にしてもよい。

## リスクと対策

| リスク | 対策 |
|---|---|
| ⭐⭐⭐ `__world` に窓を足すと (4b) が赤 | **DOM から測る**(`.worldSeal` の有無 / `#worldTitle small` の textContent) |
| ⭐⭐ `js/world-map.js` を触ると (4a) の sha1 が赤 | 封蝋は `world.html` 側だけで付ける。`seal:` などのフィールドを足さない |
| ⭐⭐ `world.html` に `localStorage.setItem` の**語**を書くと (2c) が赤 | コメントでも書かない。既存コメントの言い回し(「localStorage へ書かない」)に倣う |
| 印が出るのに入れない | **印は `questDest` から出す**。器から出さない |
| `#worldTitle` に行を足すと地図の幾何が動く | 行数を増やさず差し替える |
| `#worldTitle` にボタンを置くと札 7 枚が死ぬ | ⛔ 中には置かない。独立した固定要素にする |
| 隣窓の #63 と `tavern.html` で衝突 | **#63 の着地後に着手する**。着手前に `git status` を読む |

## 撤退スイッチ

- `?questmark=0` … 器・常時表示・封蝋をまとめて外す
- `?titleback=0` … 戻るボタンだけ外す

⭐ 2 本は**独立**。相乗りさせない(赤が出たときどちらの撤退か切り分けられなくなる)。

## changelog

**必要。** `tavern.html` を触る(器の書き / 消し / 常時表示)。プレイヤーに見える変化があるので要約は素直に書ける。

## 二重ファイル同期

`tavern.html` と `index.html` の間に同期が要る定数は無い。器の読み書きは `tavern.html` 側に閉じる。
