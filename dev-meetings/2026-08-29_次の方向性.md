# 実装候補(方向性を選んでください)

## 候補①：戦いの記録 — 帰還後レポート
- **ジャンル**: QoL / UX(フィードバックループ)
- **狙い**: オートバトルで唯一切れている「準備 → 結果 → 次の準備」の輪をつなぐ。誰が働き、誰が何に倒されたかを羊皮紙の年代記として見せる
- **ざっくり規模**: 小〜中
- **既存流用度**: **高**(`lastResult` の配管・戦闘ログ・#35 のロードアウトと直結)
- **iOS Safari**: クリア(描画のみ・音なし)
- **推し**: ノエル、レンツ ／ **慎重**: ミサキ(「単体では華がない、演出込みなら乗る」)

## 候補②：傭兵名簿 — 仲間が固有名詞になる
- **ジャンル**: メタゲーム / 愛着
- **狙い**: 使い捨てのNPCを永続化。レベルと装備を持ち、次の依頼にも同じ顔が来る。#35 のロードアウト設定が「その場限り」でなくなる
- **ざっくり規模**: **大**
- **既存流用度**: 中(マッチング画面・`allies`・ally装備は使えるが、永続キー20本への追加と二重ファイル同期が重い)
- **iOS Safari**: 要注意(localStorage 肥大・セーブスロット3つとの掛け算)
- **推し**: レンツ、ガイウス ／ **慎重**: ノエル(「死なない名簿はただのリスト、死ぬ名簿は④が無いと理不尽」)

## 候補③：冒険の賭け金 — 負傷・蘇生・撤退のコスト
- **ジャンル**: ルール / 難易度設計(D&D純度)
- **狙い**: 撤退ペナルティゼロ・敗北ノーリスクの現状に、失うものを作る。寺院での蘇生費用、負傷の持ち越し、撤退時の報酬減
- **ざっくり規模**: 中
- **既存流用度**: 中(金貨・XP・永続化は全部あるが、街に「寺院」がまだ無い)
- **iOS Safari**: クリア
- **推し**: ガイウス ／ **慎重**: ノエル(**シナリオ2 のクリア率が実測 0/3 の今これを入れると詰む**)、レンツ

## 候補④：灯りと闇 — 未踏の部屋を塗り残す(縮小版フォグ)
- **ジャンル**: 探索 / ビジュアル
- **狙い**: 仕様書にあって唯一未着手の項目。歩いた場所だけ明るく残し、未踏を闇に沈める。戦闘中の視界には触らない
- **ざっくり規模**: 小(会議中に「中 → 小」へ縮小。フル実装はオートバトルと原理的に噛み合わないと結論)
- **既存流用度**: 中(`hasLineOfSight`・訪問履歴あり)
- **iOS Safari**: 要注意(画面が狭いところをさらに削る)
- **推し**: ミサキ ／ **慎重**: ノエル、レンツ(「AIだけが全知の状態が気持ち悪い」)

> ⛔ **2026-08-31 の着手前実測で実装済みと判明 → 不採用。** 会議の根拠『`fogOfWar` の grep が
> ゼロ件』は**単語が無かっただけ**で、実体は `exploredTiles` / `visibleTiles` / `renderLighting()`
> という名前の **3 状態フォグ**(未探索=暗黒 α=255 / 探索の記憶=薄明 α=178 / 現在視界=明 α≈0)
> として既に出荷済みだった。会議で挙げた前提は 5 件とも崩れており、「歩いた場所は明るく残す」も
> 「まだ行ってない部屋は暗い」も**作る必要が無かった**。壁掛け松明も未配線ではなく、北壁の下へ
> 自動配置されてちらつく光源として発光している。⭐⭐⭐ 教訓 = **「その語で grep して 0 件」を
> 未実装の根拠にするな** —— 探すのは単語ではなく**振る舞いの名前**。
> → 代わりに「**既にある職業別の視界(8/10/12 タイル)を、プレイヤーが選ぶ瞬間の 4 箇所へ見せる**」
> へ差し替えて #39 として実装した(実装依頼書 `2026-08-31_darkvision-visible.md` §2-1)。
> ⚠ 会議で不採用にした「プレイヤーの視界だけ狭めるフル実装」は不採用のまま
> (オートバトルでは不便になるだけ、という結論は生きている)。

**会議の総意**: ①→②→③ の順を推す声が強い。②と③は「仲間の死」で表裏一体だが、どちらも①のレポートが無いと理不尽になる、というのが4人が唯一全員一致した点。④は面白いが、オートバトルという根っこと相性が悪いことが議論中に判明して規模が縮んだ。

➡️ **どの方向性を進めますか？** 選んでいただければ、その案に絞って実装会議(第2段)を開き、開発計画書を作成します。そのあと `impl-request` スキルで実装依頼書 #37 として起草するところまで進めます。

# 開発計画書：戦いの記録 — 帰還後レポート

## 概要
1回の冒険で起きたことを `RunChronicle` が記録し、帰還後に銀の鹿亭で**羊皮紙の年代記**として読める。「誰が働き、誰が何に倒され、何が空振りしたか」が事実として並び、オートバトルで唯一切れていた「準備→結果→次の準備」の輪が閉じる。**ゲームバランスの数値は1つも変えない。**

## 実装スコープ
**作る**: 記録係 `RunChronicle` / 年代記(死亡・撃破の節目) / 隊列の働き表(与ダメ・被ダメ・撃破) / 空振りの可視化(未使用スロット・未発動スキル・残存敵数) / 酒場の全画面レポート / 直近5件の記録棚
**作らない**: 助言の自動生成(ガイウス却下) / 難易度・報酬・敵の数値変更(別議題) / リザルト画面の作り替え(1行足すだけ) / `#combatLog` への変更

## 新規実装
- **`RunChronicle`(index.html)**: 単一の記録係。公開 API は `deed()`/`fall()`/`kill()`/`snapshot()` の4本だけ。**記録の出所を2つ作らない**
- **記録フック20点**: 死亡・撃破6点(Phase1) + ダメージ14点(Phase2)
- **リザルト1行**(index): 敗北時のみ「あなたを倒したのは〈◯◯〉/ 残っていた敵は N 体」
- **`#chronicleOverlay`**(tavern): 全画面羊皮紙。**明示的な閉じるボタン必須**
- **記録棚**: `dragonfighters.chronicles` に直近5件

## 実装ステップ(dev-loop 4項目)
1. **Phase1 — 記録係と年代記**: `RunChronicle` + 死亡・撃破 **6点**フック。`lastResult` へ載せ酒場に最小レポート
2. **Phase2 — 働きの集計**: ダメージ **14点**フック。隊列表を墨の棒グラフで
3. **Phase3 — 空振りとリザルト1行**: 未使用スロット・未発動スキル・残存敵数 + index のリザルトへ結論1行
4. **Phase4 — 記録棚**: 直近5件保存 + 開き直す導線 + `tools/verify_run_chronicle.js` 仕上げ

## リスクと対策
| リスク | 対策 |
|---|---|
| **20箇所のフックの入れ忘れ** | 検証ドライバで「`hp -=` の出現数」と「`chronicle.deed(` の出現数」を**配信バイトから数えて突き合わせる**。⚠ #34 の罠: **コメント内に `chronicle.deed(` と書くと1本として数えられる** |
| **`showReturnBanner` の置き換えで帰還導線の golden が壊れる** | バナーは**消さずに残す**(レポートは別 overlay)。`verify_save_slots`(5a)/`verify_town_exit`(3b)/`verify_quest_walk`(1118) が `lastResult` を縛っている |
| ⚠⚠ `verify_quest_walk`(1118) は **world.html の配信バイトに `enterVia|lastResult` が出現しないこと**を機械化 | **world.html を1バイトも触らない**。新キー名 `chronicles` は衝突しない |
| **記録が肥大して localStorage を圧迫** | 直近5件で打ち切り + 年代記の行数上限。Phase4 で実測して依頼書へ書き戻す |
| **敗北時に記録が保存されない**(gameOver 経路が複数) | 書き出しは `showResult` **1箇所**に集約。⚠ index:18642 の「探索中の罠で頭が死ぬ経路は敗北ログを1行も出さない」既知の穴は到達を実測 |
| **changelog 強制フックで commit が止まる** | 両ファイルを触るので必発。プレイヤー向け1行を Phase ごとに用意 |
