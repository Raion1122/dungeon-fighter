## 会議前の実測（本番コードで前提を確認）

提案は「軽い・平たい印象」と言うが、**実測では UI は既に"羊皮紙テーマ"を持っていた**。以下は 2026-11-26 に `tavern.html` / `index.html` / `title.html` / `town.html` / `world.html` の `<style>` を精読した結果。この実測が会議の軸を決めた。

| 観点 | 実態（実測） |
|---|---|
| デザイントークン | **`:root` のカスタムプロパティで一元化済み**。`--parchment-bg`（`linear-gradient(135deg,#f1e2bb→#e9d49a→#d8bc7e)`）/ `--parchment-ink:#3a2912` / `--parchment-gold:#8b6914` / `--parchment-border:#8b6914` / `--parchment-shadow:0 0 12px rgba(40,20,0,.6), inset 0 0 20px rgba(120,80,30,.25)` / `--wood-dark:#3a2614` `--wood-mid:#5a3a1e` `--stone:#2a251e`。**色の設計は既にトークン化されている**。 |
| ⚠ ただし共有 CSS は無い | `css/` フォルダは**存在しない**。上記 `:root` は **7 つの HTML（title/town/world/tavern/index/battle/map-editor）に各自コピーで重複**している（`:root` を全 7 ファイルで検出）。つまり**テーマ変更＝同じ `:root` を複数ファイルで言い直す**（＝ #2 の「二重ファイル同期」が 6 ファイル規模に広がる）。 |
| フォント | **`MedievalSharp`（見出し）＋`Cinzel`（本文セリフ）＋`Noto Serif JP`（語り/技能判定）を Google Fonts で読込済み**。全画面共通。→ 提案の「見出しのフォント」は**ほぼ既に満たされている**（新規フォント調達は不要）。 |
| 枠・縁 | `2px double` / `3px double` の金色二重線が主要パネルの定番。`#dialogBox` には `::before/::after` で**角飾り**が既にある。ただし**線は細く**（1〜3px）、角飾りは dialog だけ。 |
| 影・奥行き | **平ではない**。`--parchment-shadow` は外側ドロップ＋`inset` の二層で"浮き彫り/羊皮紙"感を作っている。`#dmNarration` は `border:6px solid #6a4010` ＋ `0 8px 32px` の強い影。 |
| 素材テクスチャ | **大半は CSS グラデーションで"擬似"**。実画像は `assets/tavern_bg.png`（酒場の木目）/ `assets/parchment_plaza.jpg`（看板紙）/ 各マップ背景 のみ。パネル面に紙・革・金属の実テクスチャは**ほぼ無い**。 |
| ボタン | 既に `linear-gradient` ＋ `border` ＋ hover で `transform:translateY(-1px)`／一部 active `scale(.95)`。**押し込み/ホバーの素地はある**が、ベベル（内側ハイライト＋沈み影）までは作り込まれていない。各ボタンは ID/クラス個別定義で**共有クラス化されていない**。 |
| 可読性の前科 | 過去に「文字が小さい」指摘あり（`prep-ui-ios-spec.md`）。**紙面テキストは濃茶 `#3a2912` on 明るい羊皮紙**＝今のコントラストは高い。紙面を暗くすると**この可読性が崩れる**。 |
| アニメの素地 | `index.html` に **`prefers-reduced-motion` が 13 箇所**。既にモーション軽減を尊重する前例がある＝控えめアニメは同パターンに乗れる。 |
| 平たく見える真因（推定） | テーマが無いのではなく、**①紙面が高明度（クリーム）で"重い"より"軽い"方向、②質感が実素材でなくグラデの擬似、③枠線が細い、④戦闘 HUD に浮いた現代色**（味方 HP バーが `#6af5ff→#80ffbf→#f0ffa0` のネオン・シアン→緑→黄）**が混ざって全体の格を薄めている**。 |

**→ 軸が決まった**: 提案は「テーマをゼロから足す」ではなく、**既にある羊皮紙テーマを"より深く・より実素材寄り・より枠太く"へ寄せ、浮いた現代色（HP バー等）を鎮める**作業に落ちる。しかも色はトークン化済みなので、**土台は `:root` の深色化（ただし 6 ファイル言い直し）**が最も費用対効果が高い。

## 第1ラウンド：ブレスト（各専門から枠付け）

【ガイウス】提案の狙いは正しい。だが実測が示すとおり、俺たちは"無テーマ"じゃない——**羊皮紙と金の二重線**は既にある。Gold Box の頃も、重厚さは"飾りの量"じゃなく**地の色の深さと枠の格**で出していた。Pool of Radiance のメニューは黒に近い木地に、羊皮紙の札が沈んでいた。今の俺たちは**札（紙面）は良いが、地（背景）とのメリハリと枠の太さが足りない**。だから「紙を暗くする」んじゃない。**紙の周りを深くして、紙を"荘厳な額縁に収める"**方向だ。

【レンツ】技術の地面を固める。朗報は、**色が `:root` でトークン化されてる**こと。`--parchment-gold` や `--wood-dark` を深色へ振れば、それを参照している全パネルが一斉に動く。悪い報せは、**共有 CSS が無く、同じ `:root` が 7 ファイルにコピーされてる**こと。トークンを深めるなら **title/town/world/tavern/index/battle の 6 枚を同じ値で言い直す**——これが本件の最大の隠れ工数だ。あと `index.html`/`tavern.html` を触れば **changelog フック**が「プレイヤー向け 1 行」を要求する。UI の重厚化は**見た目が変わる＝正当な changelog ネタ**だから、ここは問題にならない。

【ミサキ】見た目の話をさせて。一番"安く効く"のは**枠と地のコントラスト**よ。今は明るい羊皮紙が黒地に浮いてて"カード UI"っぽい＝それが「平たい」の正体。**金を真鍮寄りの深い金（`#8b6914`→もう少し赤みと暗さ）にして、枠を 2px→3px、主要容器に角飾り**を広げるだけで"古文書/祭壇"の格が出る。もう一歩踏むなら**小さな紙・木のタイルテクスチャ**を薄く敷きたい。のっぺりしたグラデが、繊維の見える紙になる。これは気持ちよさが段違い。

【ノエル】iPhone 番として先に釘を刺す。**可読性が最優先**。過去に「文字が小さい」が出てる。**紙面（読む面）を暗くするのは反対**——濃茶の文字が沈んで読めなくなる。深くするなら**枠・地・アクセントだけ**。あと**実テクスチャ画像は容量と iOS メモリ**。全画面の大きな紙画像を足すと、ロードも発熱も増える。**タイルで小さく・薄く**なら許す。影を厚くしすぎると iOS で描画が重くなるのも実測済み。**"重厚"を"重い（＝もっさり）"にしたら本末転倒**よ。

## 第2ラウンド：絞り込み（対立と折衷）

【ミサキ】じゃあ私の本命「実テクスチャ」から。紙の繊維・木目・金属のヘアラインは、質感の決定打なの。グラデじゃ出ない。

【ノエル】待って。全面に実画像を貼るなら容量を言って。`parchment_plaza.jpg` 級を各パネルに敷いたら iPhone が泣く。**タイル（数十 KB・繰り返し）で、`background` に薄く重ねる**なら飲める。大きなヒーロー画像は却下。

【レンツ】折衷でいこう。**実テクスチャは"縮小版"**だ。紙・木・暗石の **3 種だけ、タイル化した小さい画像**を用意し、`--parchment-bg` 等の**グラデの上に低不透明で重ねる**。既存のグラデは残すから、画像ロード前でも破綻しない（プログレッシブ）。これなら容量は数十 KB 級で、全トークン経由で一斉に乗る。本物の紙感は出るが、重さは最小。

【ガイウス】順序の話をさせてくれ。提案は「酒場ハブ先行か、全画面一括か」と聞いている。答えは**両方の良いとこ取り**だ。**色トークンの深化は"一括"で安い**（`:root` の値だけ・構造は不変）。だが**部品の作り込み（枠・ボタン・HP バー）は一括じゃ重い**から、**滞在時間の長い酒場ハブ→戦闘 HUD→町/世界**の順でいい。トークンで全体の"地の色"を一段深くしてから、部品を場所ごとに磨く。

【ノエル】HP バーに一言。味方バーの**ネオン・シアン**は、羊皮紙世界で一番浮いてる現代色。あれを鎮めるのは賛成。**でも緑＝元気・赤＝瀕死の意味は絶対に残して**。色を世界観に寄せるのはいいけど、**一目で HP が読めなくなったら UX 退行**。意味（緑/赤）を保ったまま、彩度を落として枠を付ける——それならやる価値がある。

【ミサキ】アイコンはどうする? 絵文字（🗡🪓🔨🪄🏹🛡 や 🔍⚔️💤 や 🐲）は、プラットフォーム依存でカラフル＝これも"軽さ"の一因なの。

【レンツ】そこは**見送り**だ。絵文字を独自アイコン素材へ全部差し替えるのは**美術タスクが大きい**（codex/ChatGPT 発注＋容量＋各所の差し替え）。重厚化の本丸（色・枠・ボタン）に比べて費用対効果が悪い。やるなら別チケット。**縮小代替**として"絵文字を真鍮の円メダリオン枠に収めて統一感だけ足す"手はあるが、それも今回の必須じゃない。

【ガイウス】見出しフォントは? 提案の観点に入ってるぞ。

【レンツ】**ほぼ出荷済み**だ。`MedievalSharp`＋`Cinzel`＋`Noto Serif JP` は全画面で読込済み。新規調達は不要。やることは「見出しが確実に MedievalSharp を使ってるかの徹底」だけで、これは色・枠の作業に吸収される。独立チケットにするほどじゃない。

【ノエル】演出（開閉アニメ）は? 提案は「控えめなアニメで重厚感を補えるか」と聞いてる。

【ミサキ】ダイアログ/オーバーレイが**スッと沈んで出る**だけで格が上がるわ。重い扉が閉まる感じ。

【ノエル】**条件付きで縮小 OK**。(1) dialog/overlay の**開閉だけ**（毎フレーム動かさない）、(2) **0.25 秒以内**でタップ操作を遅らせない、(3) **`prefers-reduced-motion` を尊重**（index に 13 箇所の前例あり・そこへ乗せる）。画面遷移全体に凝ったトランジションは iOS で重いので却下。

【レンツ】まとまった。**実施＝色トークン深化・枠/角飾り・ボタンのベベル**（CSS のみ・容量ゼロ・トークン経由で広く効く）。**縮小＝実テクスチャ(小タイル)・HP バー鎮静・開閉アニメ**。**見送り＝アイコン総入れ替え**（＋見出しフォントは既出荷で作業不要）。順序はトークン一括→酒場→戦闘 HUD→町/世界。

# 🎲 トリアージ結論（質感の方向性＋部品＋演出 の仕分け）

凡例: **規模** 小/中/大、**流用度** 高/中/低。実装順は「実施＋縮小版で実施」のものだけに通し番号を付す。

## 質感の方向性（最上位の分岐）

### 方針X デザイントークンの深化（配色）→ 🟢 実施（本命・土台）
- **理由**: 色は `:root` でトークン化済み。`--parchment-gold`・`--wood-dark`・`--parchment-border`・`--parchment-shadow` を**深色・真鍮寄り**へ振れば、参照している全パネルが一斉に重厚化する。**CSS 値のみ・構造不変・容量ゼロ**。既存の二重線/影/セリフ体という"素地"にそのまま乗る。
- **中身**: ①アクセント金を真鍮寄りの深い金へ、②枠色・地の木目・石を一段暗く、③`--parchment-shadow` の外側ドロップと inset を少し強め、④**紙面（読む面）＝`--parchment-ink`/`--parchment-bg` の明度は据え置き**（可読性保護）。地と枠とアクセントだけ深める。
- **コスト注意**: 共有 CSS が無いので **`:root` を 6 ファイル（title/town/world/tavern/index/battle）で同値に言い直す**のが隠れ工数。将来は共有 CSS 化も検討余地（本件スコープ外）。
- **規模** 小〜中 ／ **流用度** 高 ／ **iOS** クリア（値変更のみ）。 **実装順**: ①番目（土台・全画面一括で効く）。

### 方針Y 実素材テクスチャ（紙・木・金属・石の実画像）→ 🟡 縮小版で実施（小タイルを薄く重ねるだけ）
- **理由**: グラデの擬似質感を本物の繊維/木目へ上げると"質感"の決定打になる。ただし大きなヒーロー画像は**容量・iOS メモリ・ロード**を増やす（提案の制約「読み込み速度・容量」に抵触）。
- **縮小の中身**: **紙・木・暗石の 3 種だけ、タイル化した小さい画像（各数十 KB・繰り返し可）**を用意し、既存グラデの**上に低不透明で重ねる**（画像未ロードでもグラデで破綻しない＝プログレッシブ）。全面貼りはしない。まず酒場ハブの主要パネル 1 面で手応えを見る。
- **規模** 中 ／ **流用度** 中 ／ **iOS** 要注意（容量チェック必須）。 **実装順**: ⑤番目（色・枠・ボタンの後。物足りなければ）。

## 部品ごと

### ① 枠・縁の強化＋角飾り → 🟢 実施（ヒーロー容器限定）
- **理由**: 二重線と `#dialogBox` の角飾りという素地がある。これを**主要容器（ダイアログ／語り部枠／ステータス大パネル／酒場の受注器）**へ広げ、線を 2px→3px、角飾りを付けると"古文書/祭壇"の格が一気に出る。CSS のみ・容量ゼロ。
- **縮小的運用**: **小さなカードや全ボタンには角飾りを付けない**（busy 化＋スマホのタップ領域圧迫を避ける）。重い額縁は"主役の器"だけに。
- **規模** 中 ／ **流用度** 高 ／ **iOS** クリア。 **実装順**: ②番目。

### ② ボタンの押し込み感・ベベル・ホバー → 🟢 実施（主要ボタンから）
- **理由**: 既に gradient＋hover translateY／一部 active scale の素地あり。**内側ハイライト＋沈み影のベベル**と**押下時に本当に沈む active 状態**、縁を真鍮リムにすると"金具"の手触りになる。
- **コスト注意**: ボタンは共有クラス化されておらず ID/クラス個別。**まず主要アクション（出発する／受注／ショップ）から**共通の"重厚ボタン"見た目を当て、順次広げる。
- **規模** 中 ／ **流用度** 中（個別定義のため言い直し多め）／ **iOS** クリア。 **実装順**: ③番目。

### ③ HP バーの質感統一（現代色を鎮め枠を付ける）→ 🟡 縮小版で実施（意味＝緑/赤は保持）
- **理由**: 味方バーの**ネオン・シアン**は羊皮紙世界で最も浮く現代色＝"平たさ/ちぐはぐ"の一因。枠（真鍮リム）＋沈んだトラック＋彩度を落とした塗りで世界観に寄せる。
- **縮小＝守る線**: **緑＝元気・赤＝瀕死の一目読みは絶対維持**（UX 退行禁止）。色は世界観寄りに鎮めても、HP の状態識別性は落とさない。まず味方バー（`.allyHpFill` のネオン）を落ち着いた琥珀/血色寄りへ、`hpChip` は既に羊皮紙枠なので微調整のみ。
- **規模** 小〜中 ／ **流用度** 高 ／ **iOS** クリア。 **実装順**: ④番目。

### ④ アイコンの統一感（絵文字→独自素材 or 枠で統一）→ 🔴 見送り（美術タスク大・別チケット）
- **理由**: 絵文字（🗡🪓🔨🪄🏹🛡／🔍⚔️💤／🐲 等）はプラットフォーム依存でカラフル＝軽さの一因だが、**独自アイコン素材への全面差し替えは美術タスクが大きく**（codex/ChatGPT 発注＋容量＋各所差し替え）、色・枠・ボタンの本丸より費用対効果が低い。
- **再検討条件**: 色・枠・ボタン・テクスチャまで入れても"アイコンだけ浮く"と判断されたら別チケットで。**縮小代替**＝"絵文字を真鍮の円メダリオン枠に収めて統一感だけ足す"（絵素材を作らず CSS 枠のみ）も、その時の候補。

### ⑤ 見出しフォント → ✅ ほぼ出荷済み（新規作業ほぼ無し）
- **理由**: `MedievalSharp`＋`Cinzel`＋`Noto Serif JP` を全画面で読込・使用済み。提案の「見出しのフォント」は既に満たされている。やることは「見出しが確実に装飾体を使っているかの徹底」だけで、方針X／①の作業に吸収される。独立チケット不要。

## 演出面

### ⑥ 開閉の控えめアニメ → 🟡 縮小版で実施（dialog/overlay の開閉だけ）
- **理由**: ダイアログ/オーバーレイが"スッと沈んで出る"だけで格が上がる。ただし**画面遷移全体の凝ったトランジションは iOS で重い**ので却下。
- **縮小＝守る線**: (1) dialog/overlay の**開閉のみ**（毎フレーム animate しない）、(2) **0.25 秒以内**でタップを遅らせない、(3) **`prefers-reduced-motion` を尊重**（index.html に 13 箇所の前例・そこへ乗せる）。
- **規模** 小 ／ **流用度** 高 ／ **iOS** クリア（条件順守時）。 **実装順**: ⑥番目（任意・余力で）。

## 適用範囲と順序について（提案の「酒場ハブ先行か全画面一括か」への回答）
- **色トークン（方針X）は"全画面一括"が安い**（`:root` の値変更のみ・構造不変）。ただし共有 CSS が無いため **6 ファイルで同値に言い直す**規律が要る。
- **部品の作り込み（①②③）は"場所ごと"**。順序は**滞在の長い酒場ハブ → 戦闘 HUD(index) → 町(town)/世界(world)/タイトル(title)**。
- まとめると「**トークンで地の色を一段深くする（一括）→ 酒場で枠・ボタン・テクスチャを磨く → 戦闘 HUD の HP バー等を鎮める → 残り画面へ波及**」。

# 📌 実装順サマリ（実施＋縮小版の推奨順）

CSS 中心・容量ゼロ寄りで「重厚感」を最短で上げる順。Phase 1（①〜③）だけで体感は大きく変わる。

**Phase 1（本丸・CSS のみ・容量ゼロ）**

5. **方針Y 実テクスチャ（小タイル）**（紙/木/暗石 3 種を薄く重ねる・容量確認）… 工数 **1 日**
6. **⑥ 開閉の控えめアニメ**（dialog/overlay のみ・reduced-motion 尊重）… 工数 **0.5 日**

**合計見立て**: Phase 1 だけで **約 2〜3 日**（CSS のみ・容量ゼロ）。Phase 2 まで含めて **約 4〜5 日**。

**見送り（今回やらない）**: ④ アイコン総入れ替え（美術タスク大・別チケット）。⑤ 見出しフォントは既出荷で作業不要。

**守るべき制約への回答（提案の 5 つ目の観点）**:
- **可読性**: 紙面（読む面）の明度・文字色は**据え置き**。深色化は枠・地・アクセントのみ。過去の「文字が小さい」に配慮し**文字サイズは下げない**。コントラストは実機で確認。
- **スマホ表示**: 角飾り・重枠は**主要容器限定**（小カード/全ボタンに付けない＝タップ領域とごちゃつき回避）。
- **読み込み速度・容量**: Phase 1 は**容量ゼロ**（CSS 値のみ）。テクスチャは**小タイル（数十 KB）を薄く重ねる**縮小版に限定し、大きなヒーロー画像は使わない。
- **既存機能・レイアウト**: 構造 HTML は変えず CSS の値・追加のみ。**クリティカル演出（ヒットストップ閃光）・フォグオブウォー・語り部 UI・フェーズ表示・changelog 枠**は非変更。
- **changelog フック**: `index.html`/`tavern.html` を触るので**プレイヤー向け 1 行の更新情報が必須**（CLAUDE.md ルール）。UI 重厚化は見た目の変化＝正当な changelog ネタで、迂回不要。

# ❓ sakata に判断を求める点

1. **紙面を暗くするか、枠・地・アクセントだけ深めるか**（最重要）。**推奨＝紙面（読む面）は明るいまま据え置き、枠・背景・金アクセントだけ深色化**。過去に「文字が小さい」が出ており、紙面を暗くすると濃茶文字の可読性が崩れる。
2. **実テクスチャ画像を入れるか、CSS のみで通すか**。**推奨＝まず Phase 1（CSS のみ・容量ゼロ）で手応えを見て、物足りなければ小タイル 3 種（紙/木/暗石）を薄く重ねる**。大きな紙画像の全面貼りは iOS 容量・メモリで却下。
3. **アイコンを絵素材で作り直すか**。世界観的に絵文字は浮くが美術タスクが大きいので、**推奨＝今回は見送り（別チケット）**。やるなら"真鍮メダリオン枠で統一"の CSS 縮小版から。
4. **適用順＝酒場ハブ先行でよいか**。**推奨＝色トークンは全画面一括（安い）→ 部品は酒場→戦闘 HUD→町/世界/タイトルの順**。
5. **開閉アニメを入れるか**。**推奨＝入れるなら dialog/overlay の開閉のみ・0.25 秒以内・`prefers-reduced-motion` 尊重**。画面遷移全体の凝った演出は iOS 配慮で見送り。
