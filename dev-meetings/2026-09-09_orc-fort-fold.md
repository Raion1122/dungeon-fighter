# 開発会議〔第1段：候補出し〕：砦を卓上マップ 2 枚へ畳む(F2)

**議題**: シナリオ4「廃墟の砦 orc-fort」の 8 ノードを卓上大部屋へ畳む(旧タイプ MAP 全廃計画の F2)。
論点は 2 つ — (a) 8 ノードをどう割るか、(b) **休眠する古代王国の守護者 5 体をどこへ置くか**。
**ゴール**: 毛色の違う候補を出して、進む方向を 1 つ選ぶ

## 会議前の実測(起草窓が本番コードで測った値・2026-09-09)

### 砦の現状

- `buildOrcFortRun`(`index.html:37474`)は `buildP6Run` に n0〜n7 を渡し、**戻り値も 8 ノードのまま**(畳み済みではない)
- 敵の在庫 = **オーク 13 体**(n1:3 / n2:2 / n3:2 / n4:4 / n7:2)+ ガロック 1 + **守護者 5 体**(n6)
- 絵は `room_orc-fort_n4.jpg`(7列x6行) / `_n7.jpg`(9列x6行)の**旧絵 2 枚だけ**。卓上マップ(`*_map.jpg`)は **0 枚**
- ノードの kind: n0 start / n1 combat / n2 **search** / n3 **loot** / n4 combat / n5 **rest** / n6 event / n7 boss
- 罠 5 + 隠し宝箱 4(`index.html:10574`)。湧き口は n2(search) と n3(loot) の 2 ノードだけ
- 大部屋の上限は `MAP_W=72` / `MAP_H=28`。既存の実績は 森 n7big **52x26** / 沼 n4big **30x21** / 廃坑 n1 **39x23**

### ⭐⭐⭐ 守護者 5 体を大部屋へそのまま移すと「クリア不能」になる

4 つの実測が噛み合う:

1. `initGuardians`(`index.html:24166`)は `inactive` と `dormant` を立てるが **`passiveNpc` は立てない**
2. `isNodeSettled()`(`index.html:36329`)は `enemies.every(e => !e.alive || e.passiveNpc)` を要求
   ⇒ **休眠中の守護者が 1 体でも居ればノードは永久に未決着 = 出口の矢印が出ない**
3. `findNearestAliveEnemy()`(`index.html:18643`)も heroAI の ④(`index.html:18984`)も
   **`e.inactive` を除外する** ⇒ パーティは休眠中の守護者へ**歩かない**。
   ④ が null を返すと `targetX = null` で**その場に停止する**
4. `GUARDIAN_AWAKEN_RADIUS = 270`px = **2.8 タイル**。しかも `tryAwakenGuardian`(`index.html:24205`)は
   `encounterActive || encounterRunning` の間は**必ず return** = 乱戦中は覚醒しない

⭐ **今 n6 が詰まないのは、7x6 の小部屋で入場地点から守護者まで 1〜2 タイルしかないという幾何の偶然**。
大部屋へ移した瞬間に (3) と (2) が噛み合って詰む。既知欠陥 `spawn_on_gate_stall` と**同型**
(isNodeSettled が永久 false)。

### ⛔ 2026-09-08 の計画書の主張が 1 件崩れた

計画書は「分岐の楽しさは P9 の**部屋内の寄り道**で代替する」と書いたが、
寄り道の提示(`tickNodeChoice` / `index.html:36460-36469`)は **`isNodeSettled()` の後ろ**にある。
⇒ 守護者が居る限り**寄り道そのものが出ない**。**P9 では守護者問題は解けない。**

さらに計画書の砦の行は「**発注 2 枚**」だが、**n6(忘れられた廟)の隠し要素の行き先は書かれていない**。
2 枚に畳むなら、廟は「道中マップの中」へ入るしかない。

### F1(沼 #62)から引き継ぐ型

- `FOLD_MOVED_N4` で消えるノードの敵を**体数も種類も変えずに**大部屋へ移設
- `NODE_EXTRA_SPAWN_KINDS` に `{ n4: ["search","loot"] }` の兼務宣言(**忘れると罠も宝箱も無言でゼロ**)
- `SWAMP_FOLDED = !SWAMP_FOLD_OFF && !SWAMP_MAP_OFF`(撤退スイッチは派生を 1 箇所で作る)
- 群の数は**絵の寸法で決まる**(沼 30x21 では 2 群が上限・`DETECTION_RANGE` = 12.5 タイル)。
  ⭐ 砦は**これから発注する**ので、**寸法そのものが設計変数**になる

# 実装候補(方向性を選んでください)

## 候補①：守護者を「仕掛け」にして道中マップへ組み込む — 発注 2 枚
- **ジャンル**: システム(スポーンと寄り道の配線)
- **狙い**: 廟を道中マップの一角として絵に描き、**守護者は敵スロットに書かない**。
  乱戦を片付けると P9 の寄り道「崩れた廟へ寄るか?」が出て、**選んで歩いた時に 5 体を湧かせる**
- **ざっくり規模**: 中(発注 2 枚 + 「到達時に湧かせる」新規配線)
- **既存流用度**: 中 — P9 の寄り道は流用できるが、**寄り道到達をトリガに敵を湧かせる前例は無い**
- **iOS Safari**: クリア(走行は 8 部屋 → 2 部屋で短くなる)
- **推し**: レンツ ／ **慎重**: ミサキ(絵と選択肢の対応が薄いと宙に浮く)

## 候補②：廟を独立ノードで残す — 発注 3 枚(道中 / 廟 / ボス)
- **ジャンル**: 構造・素材(沼 #62 と同じ 3 ノードの形)
- **狙い**: 沼地とまったく同じ形。道中(start)→ ボス(本道)、道中 → 廟(行き止まりの寄り道)。
  廟は**小さめの卓上マップ**(20x14 程度)にして、**入場口から祭壇まで 3 タイル以内**に守護者を置く
- **ざっくり規模**: 中(発注 3 枚。ただし**新規コードはゼロ** = #62 の形をなぞるだけ)
- **既存流用度**: **高** — `SWAMP_FOLDED` / `FOLD_MOVED_N4` / 兼務宣言をそのまま写せる
- **iOS Safari**: クリア(走行 8 → 3 部屋)
- **推し**: ミサキ・レンツ ／ **慎重**: ノエル(1 走行が候補①より長い)

## 候補③：守護者に `passiveNpc` を与えて完全に任意の存在にする — 発注 2 枚
- **ジャンル**: エンジン(1 行の述語変更)
- **狙い**: `initGuardians` で休眠中は `passiveNpc = true` も立てる。`isNodeSettled` を塞がなくなるので
  道中マップのどこに置いても詰まない。**接近すれば覚醒して戦える**
- **ざっくり規模**: **小**(発注 2 枚 + `initGuardians` に 1 行)
- **既存流用度**: 高
- **iOS Safari**: クリア
- **⛔ 既知の弱点**: heroAI は `inactive` を目標にしないので、**オートバトルでは誰も近づかない**
  = 隠し要素が事実上「実装されているが永久に出会えない」状態になる。⭐ 誘導は別途要る
  (寄り道スポットを廟に置く = 結局①と同じ配線)
- **推し**: (なし) ／ **慎重**: 全員 — **単独では成立しない**が、①②の**下敷きとして併用する価値はある**

## 候補④：守護者を廃止し、砦を純粋なオークの砦にする — 発注 2 枚
- **ジャンル**: スコープ削減
- **狙い**: 守護者 5 体を砦から外し(`?fortguard=1` で戻せる形で退避)、F2 を**畳むことだけ**に絞る。
  第三勢力は F3/F4 の後で「砦の隠し要素」チケットとして独立に立て直す
- **ざっくり規模**: **小**(発注 2 枚。守護者の配線は 1 行も触らない = 沼 #62 と完全に同型)
- **既存流用度**: **最高**
- **iOS Safari**: クリア(1 走行が最も短い)
- **⛔ 代償**: `fort-golems.md` の隠し要素が一時的に画面から消える。XP も 1500x1 + α ぶん減る
- **推し**: ノエル(まず畳みを通す) ／ **慎重**: ガイウス(隠し要素を消すのは負け筋)

# 開発会議〔第2段：実装計画〕：候補④ 守護者を一旦廃止して砦を 2 枚へ畳む

**選択案**: 砦を **卓上大部屋 2 枚(道中 + ボス)** へ畳む。休眠する守護者 5 体は畳んだ構成に載せず、

**ゴール**: この案を実装依頼書 #63 に落とせる粒度の開発計画書にする

## ⚠ 第1段の候補文の訂正(第2段の冒頭で判明)

第1段の候補④は「`?fortguard=1` で戻せる形で退避」と書いたが、**専用スイッチは要らない**。
畳んだノード表に n6 を載せないだけで守護者は既定の走行から消え、`?fortfold=0` は
`buildP6Run` の 8 ノード構成をそのまま返すので**守護者ごと復活する**。
⛔ むしろ専用スイッチを足すと「守護者だけ居て廟が無い」中間状態を作れてしまう
(#62 が `?swampfold=0` / `?swampmap=0` の派生を 1 箇所に集めたのと同じ理由)。

## ⭐⭐⭐ 第2段の冒頭で測った、母集団の本丸

`tools/goldens/grid_s2.json` に **砦の 8 ノードの mapDef が丸ごと JSON で焼かれている**
(name / rect / enemySlots / painting まで)。そして `tools/driver_grid_s2.js:87` は
`const UNTOUCHED = ['orc-fort', 'undead-temple', 'dragon-lair'];` と書いて、
**この 3 本を「畳んでいないシナリオ」として既定の腕で golden と突き合わせている**。

⭐ そして **#62 は沼をこのリストから外し、`?swampfold=0` の腕へ移すだけで回収した**
(`driver_grid_s2.js:703-717`。⭐⭐⭐ **golden のキーも assert 本体も 1 文字も書き換えていない**)。
F2 は**同じ操作を砦に対してやる**。前例が完全に揃っている。

⚠ ただしこれは「`?fortfold=0` の腕では 8 ノードが**1 バイトも変わらない**」ことが前提。
⇒ **新しい大部屋は、畳んだ既定の腕にだけ出すこと**。旧絵 `room_orc-fort_n4.jpg` / `_n7.jpg` と
7x6 / 9x6 の rect は撤退の腕にそのまま残す。

## 第1ラウンド：設計

【レンツ】形は #62 の写しでいい。`buildOrcFortRun` の末尾に `if (!FORT_FOLDED) return run;` を置いて、
その下で `run.nodes` から **n4 と n7 だけを取り出す**。n4 の kind を `"start"` にして entry にし、
exits は `buildP6Run` が作った right → n7 をそのまま持ち上げる。
⭐ **mapDef はここで組み直さない** —— 沼で決めた作法どおり、`buildP6Run` が作ったものを
そのまま取り出す。組み直すと「畳んだ版と畳んでいない版で幾何が違う」中間状態が生まれる。

【レンツ】敵は **11 体**を道中(n4)へ移す。旧 n1 の 3 + 旧 n2 の 2 + 旧 n3 の 2 + n4 の 4。
種類も数も変えない —— orcBerserker 3 / orcGrunt 4 / orcArcher 2 / orcShaman 2。
沼の折り畳み後の n4 も**ちょうど 11 体**で、30x21 の絵に 2 群で収まっている。**同じ規模で足りる**。
ボスノードは護衛 2 + ガロックのまま **1 ビットも動かさない**。

【レンツ】罠と宝箱は必ず落とすな。n2(search) と n3(loot) が消えるので、
`NODE_EXTRA_SPAWN_KINDS` に `"orc-fort": { n4: ["search","loot"] }` を **FORT_FOLDED のときだけ**足す。
⛔ 忘れると罠 5 個と隠し宝箱 4 個が**無言でゼロ**になる(森 #16 で実際に踏んだ)。

## 第2ラウンド：肉付けと衝突

【ミサキ】発注の話。2 枚とも**砦の内部**だから、森や沼の屋外マップとは作法が違う。
**壁で閉じた構図**にして `outdoor: true` は付けない —— フォグオブウォーが効いたほうが
「砦を制圧していく」感じが出る。道中は西の崩れた城門から入って、中庭 → 兵舎跡 → 東の練兵場。
ボスは主塔の広間、玉座と軍旗。

【ノエル】寸法で 1 つ注文がある。**行数は奇数にして**。`nodeGateTile` は `Math.floor` で
辺の中点を出すから、行数が偶数だと**入場行が 1 マスずれる**(#58 で踏んだ)。
沼の n4big は 21 行(奇数)で素直だったけど、n7big は 20 行(偶数)で気持ち悪かった。
**発注するのはこっちなんだから、最初から奇数で頼めばいい。**

【ミサキ】それは賛成。ただ**サイズは大きめにしたい**。道中が 30x21 だと沼と同じで、
「砦」という言葉から来る威圧感が出ない。**39x23(廃坑 n1 と同じ)**まで広げたい。

【ノエル】反対。**11 体しか居ない部屋を 39x23 にすると、スカスカの石畳を延々歩くだけ**になる。
沼の 30x21 で 11 体は密度がちょうどよかった。iPhone は 1 画面 7.7x6.2 タイルしか映らないから、
広い部屋は「歩いてる時間」がそのまま増える。走行を短くするのが F2 の目的でしょ。

【ミサキ】……じゃあ**道中は 31 列 x 21 行**で。沼とほぼ同じ密度で、幅だけ 1 列足す。
その代わり**ボス部屋は狭くしていい** —— 29 列 x 19 行。ガロックは単騎 + 護衛 2 だから、
玉座まで一直線に対峙する画のほうが強い。

【ガイウス】絵に 1 つ注文がある。**廟の痕跡は道中マップに描いておいてくれ。**
守護者を出さないのは今回の判断だが、`fort-golems.md` の設定を捨てたわけじゃない。
中庭の隅に**崩れた古代王国の廟と、割れた石像の足元**が描かれていれば、
後で守護者を戻すときにそこへ置ける。**絵は設定より長生きする。**

【ノエル】それは同意。ただ**今回は絵だけ**ね。石像を「敵として置ける」ようにした瞬間に
第1段の詰みの話が全部戻ってくる。

【ガイウス】もう 1 つ。**n5「井戸端」の全快が消える**。廃坑 P8 と沼 #62 で同じ判断をしているから
今回も復活させないが、砦は**★★★ の難易度**だ。廃坑や沼より厳しく効く。
ここは「難易度・XP の再調整」チケットへ確実に持ち越すこと。
